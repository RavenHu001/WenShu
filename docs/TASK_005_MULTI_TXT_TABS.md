## 一、任务目的

Task 4 已建立“工作区文件树 → 受控 TXT 读取 → CodeMirror 编辑 → revision 冲突检测 → 安全保存”的单文档闭环。本任务在不修改主进程文件访问权限、不引入搜索、自动保存、文件管理或 DOCX 的前提下，把单文档状态扩展为可靠的多标签编辑会话：

```text
从文件树打开多个工作区内普通 UTF-8 TXT
  -> 每个规范相对路径只对应一个标签
  -> 标签独立维护读取、正文、版本、dirty、saving、错误与冲突状态
  -> 切换标签保留 CodeMirror 光标、选区、滚动位置和撤销历史
  -> 当前标签通过现有受控 API 显式保存
  -> 关闭标签、切换工作区或关闭窗口时保护全部未保存内容
```

本任务的核心目标不是只画出一排标签，而是建立可以继续承载搜索、DOCX 和会话恢复的多文档状态基础，同时保持 Task 4 已验证的数据安全与 Electron 边界。

## 二、完成后的用户体验

任务完成后，用户应能够：

1. 从文件树连续打开多个 UTF-8 `.txt` 文件，每个文件显示为一个标签；
2. 点击标签在多个文档之间切换，切换过程无额外磁盘读取和明显等待；
3. 再次打开已经存在的文件时直接激活原标签，不创建重复标签；
4. 在不同标签中独立编辑，正文、未保存标记、保存状态、错误和外部冲突互不污染；
5. 切换标签后保留各自的光标、选区、滚动位置和撤销/重做历史；
6. 通过保存按钮或 `Ctrl+S` 保存当前活动标签；
7. 在不同标签之间并行保存，但同一标签不会产生并发保存请求；
8. 关闭普通标签；关闭含未保存修改的标签前得到“放弃修改 / 取消”确认；
9. 通过 `Ctrl+W` 请求关闭当前活动标签，并遵循同一未保存保护流程；
10. 关闭活动标签后按确定规则激活相邻标签；关闭最后一个标签后回到欢迎页；
11. 切换工作区或关闭窗口时，对所有未保存标签进行聚合保护；
12. 某个标签读取失败、保存失败或发生外部冲突时，其他标签仍可正常编辑和保存。

## 四、固定设计决策

### 4.1 单工作区内的多 TXT 标签

- 本任务仍只支持一个工作区根目录；
- 只为当前已支持的普通 UTF-8 `.txt` 文件创建文档标签；
- 每个标签只持有规范工作区相对路径，不持有工作区根路径或任意绝对路径；
- 工作区成功切换后，旧工作区的全部标签和运行时会话失效；
- 不建立跨工作区标签、最近文件或持久化恢复。

### 4.2 标签身份与去重

- 在单工作区会话内，以文件树提供并经既有规则规范化的 `relativePath` 作为标签稳定身份；
- 同一路径在 `loading`、已加载或错误状态下都只能存在一个标签；
- 再次从文件树选择已打开路径时只激活已有标签，不重新读取、不重置正文、不清除错误和撤销历史；
- 文件名相同但相对路径不同的文件必须允许同时打开；标签至少通过 tooltip 和无障碍名称暴露完整相对路径，可选显示最短父目录用于视觉区分；
- 不使用数组下标作为标签身份。

### 4.3 标签顺序、激活与关闭

- 新标签追加到标签序列末尾并立即激活；
- 点击标签只改变活动标签，不触发未保存确认；
- 关闭非活动标签不改变当前活动标签；
- 关闭活动标签后优先激活其右侧标签；没有右侧标签时激活左侧标签；
- 关闭最后一个标签后显示欢迎页，文件树不再高亮文档；
- 标签栏允许横向滚动；项目基线建议同时打开 20 个以内，本任务不建立复杂淘汰或虚拟化机制；
- 标签拖拽排序、固定、批量关闭、分组和分屏不在本任务范围内。

### 4.4 每标签独立状态

每个标签至少独立维护：

- `id` / `relativePath`；
- `name`；
- `status`；
- 最后一次成功读取或保存的 `document` 快照；
- 当前 `content`；
- `dirty`；
- `saving`；
- 最近一次读取或保存 `error`；
- 编辑修订号、读取请求号和保存请求上下文；
- CodeMirror 编辑会话状态。

标签状态至少包括：

- `loading`；
- `loaded-clean`；
- `loaded-dirty`；
- `saving`；
- `save-error`；
- `conflict`；
- `read-error`。

“尚无标签”由顶层空集合表达，不为欢迎页创建伪文档标签。

### 4.5 状态管理边界

- 将多标签集合和活动标签行为集中在独立 controller/hook 中，避免 `App.tsx` 同时承担数组更新、竞态和界面渲染；
- 优先使用纯 TypeScript 状态转移函数或 React reducer，使打开、激活、编辑、保存完成、关闭和失效行为可单元测试；
- 编辑器 `EditorView`、`EditorState`、Promise、函数和计时器不得进入共享 IPC 契约或持久化数据；
- 本任务默认不引入 Zustand 或其他全局状态库；只有现有 React 状态模型经实际实现证明无法维护时，才可记录问题、收益和迁移成本后提请项目所有者决定；
- 不为未来 DOCX 或插件系统预建通用文档框架。

### 4.6 CodeMirror 会话隔离

- 每个标签必须拥有独立的 CodeMirror 状态；切换标签不能把上一标签的撤销历史带入下一标签；
- 切回标签时应恢复其光标、选区、滚动位置和撤销/重做历史；
- 推荐由 `TextEditor` 或专用编辑器宿主在 renderer 内用 `Map<tabId, EditorState>` 等非序列化引用缓存会话：切出前保存当前状态，切入时恢复对应状态；
- 不建议为了保留状态而同时挂载并隐藏最多 20 个完整 `EditorView`，避免多个大文件造成不必要的 DOM 和内存开销；
- 首次加载、冲突确认后的重新读取或其他明确的磁盘正文替换应为该标签创建新的编辑器状态并清除旧撤销历史；
- 普通标签切换不得重建编辑器状态；
- 关闭标签或切换工作区后必须释放对应缓存，不保留不可达的编辑器对象或闭包。

### 4.7 读取、打开失败与竞态

- 选择新路径时先创建并激活唯一的 `loading` 标签，再调用现有 `document.readText(relativePath)`；
- 初次读取失败时保留一个可关闭的 `read-error` 标签，显示稳定错误和重试入口；不覆盖或清除其他已加载标签；
- 对已经成功加载的标签执行重新读取失败时，保留原正文、dirty 和已保存快照，并显示非阻塞错误；
- 每个标签的读取请求独立编号；A、B 同时读取时，结果只可提交到各自标签；
- 标签已关闭、工作区已切换或该标签已有更新读取请求时，迟到结果必须忽略；
- 对已存在标签的普通激活不发起读取；只有明确“重试”或冲突后的“重新读取”才发起新请求。

### 4.8 保存与并发语义

- 保存按钮和 `Ctrl+S` 默认只保存当前活动标签；
- 未修改标签触发保存时不调用 IPC；
- 同一标签同一时刻最多一个保存请求在途；
- 不同标签允许各自最多一个保存请求并行，不设置全局保存锁；
- 保存请求捕获目标标签、正文、编辑修订号和已保存 `revision`；
- 保存成功只有在该标签当前编辑修订号仍等于捕获值时才清除 dirty；保存期间的新编辑必须保留；
- 保存成功始终只更新目标标签的已保存快照和 revision，不改变其他标签或当前活动标签；
- 保存失败、IPC Promise 拒绝和 `CONFLICT` 只更新目标标签，保留其正文和 dirty；
- 混合换行确认、冲突重新读取等延迟交互必须绑定发起它的 `tabId`，不能在用户切换标签后误操作新的活动标签；
- 本任务不增加“全部保存”、自动保存、强制覆盖、另存为或保存队列。

### 4.9 未保存修改与正在保存保护

- 切换标签和打开另一个 TXT 不再要求放弃当前修改，因为原标签仍保留；
- 关闭 dirty 标签时显示应用内“放弃修改 / 取消”确认，确认对象必须是请求关闭的标签，而不是确认时恰好活动的标签；
- 关闭 clean 标签无需确认；
- `Ctrl+W` 与关闭按钮必须调用同一关闭入口；
- 切换工作区时，若存在一个或多个 dirty 标签，应显示聚合提示，至少包含未保存标签数量；确认后仅在工作区实际切换成功时清除旧标签；取消或目录选择失败时全部保留；
- 关闭窗口时，`window.setDirtyState()` 上报 `tabs.some(tab => tab.dirty)`，主进程继续只维护最小布尔状态；
- 窗口关闭确认至少显示未保存标签数量；确认放弃后才调用既有 `requestClose()`，取消时调用 `cancelClose()`；
- 对正在保存的标签，不允许关闭该标签、切换工作区或关闭窗口；应取消本次过渡并提示等待保存完成，避免把已经开始的磁盘写入错误描述为可撤回的“放弃修改”；
- 本任务继续采用“放弃修改 / 取消”，不加入“保存并关闭”或多文档保存编排。

### 4.10 工作区刷新与外部变化

- 刷新工作区不关闭标签、不重读正文、不清除 dirty、错误或撤销历史；
- 刷新后文件从树中消失，标签仍保留；后续保存或明确重新读取由现有主进程校验返回稳定错误；
- 文件树高亮只跟随当前活动且有规范路径的标签；活动错误标签也可按其路径高亮；
- 本任务不加入文件系统监听、自动刷新或后台冲突提示。

## 五、建议的 renderer 数据模型

以下类型用于明确语义，不要求逐字照搬命名：

```ts
type TextTabStatus =
  'loading' | 'loaded-clean' | 'loaded-dirty' | 'saving' | 'save-error' | 'conflict' | 'read-error';

interface TextDocumentTabState {
  readonly id: string;
  readonly relativePath: string;
  readonly name: string;
  readonly status: TextTabStatus;
  readonly document: TextDocumentSnapshot | null;
  readonly content: string;
  readonly dirty: boolean;
  readonly saving: boolean;
  readonly error: TextDocumentError | SaveTextDocumentError | null;
}

interface TextDocumentsUiState {
  readonly tabs: readonly TextDocumentTabState[];
  readonly activeTabId: string | null;
}
```

运行时竞态元数据建议与可渲染状态分离：

```ts
interface TextTabRuntime {
  editRevision: number;
  readRequestId: number;
  saveInFlight: boolean;
  latestContent: string;
}
```

固定不变量：

1. `tabs` 中 `id` 和 `relativePath` 唯一；
2. `tabs` 为空时 `activeTabId === null`；
3. `tabs` 非空时 `activeTabId` 必须引用现有标签；
4. `saving === true` 时该标签存在且只有一个保存请求在途；
5. dirty 的清除只能来自与当前编辑修订匹配的成功保存或明确放弃/重新读取；
6. 任一异步结果提交前必须同时验证工作区会话、目标标签和请求编号仍有效。

## 六、组件与文件职责建议

### 6.1 多文档 controller

将 `use-text-document.ts` 重构或替换为多文档 controller，例如：

- `use-text-documents.ts`：管理异步读取/保存、运行时引用和面向 UI 的命令；
- `text-document-tabs.ts`：可选的纯状态转移函数、reducer、选择器和不变量；
- `use-text-document.ts` 可删除、保留兼容薄层或改名，但不得同时维护两套真实状态。

controller 至少暴露：

- `openTextFile(relativePath)`；
- `activateTab(tabId)`；
- `editTab(tabId, content)`；
- `saveTab(tabId, options?)`；
- `retryRead(tabId)`；
- `reloadTab(tabId)`；
- `requestCloseTab(tabId)` 所需的状态信息；
- `closeTab(tabId)`；
- `invalidateWorkspace()`；
- `hasDirtyTabs`、`dirtyTabCount` 与 `hasSavingTabs` 选择结果。

### 6.2 标签栏

新增独立标签栏组件，避免继续把标签渲染和正文状态分支全部堆入 `DocumentPane`：

- 标签使用可聚焦、可键盘激活的控件；
- 活动标签暴露 `aria-selected` 或等价语义；
- 关闭按钮具有包含文件名的可访问名称；
- dirty 标记不能是唯一的状态表达，需同时提供可访问文本；
- 完整相对路径通过 `title` 或等价方式可发现；
- 横向溢出不能挤压或覆盖保存工具条。

### 6.3 文档面板与编辑器宿主

- `DocumentPane` 只渲染活动标签或欢迎页；
- 标签栏与文档正文使用同一个 `activeTabId` 快照，避免标签标题与正文错位；
- 保存状态、错误横幅、冲突重新读取和混合换行确认均从目标标签状态派生；
- CodeMirror 会话缓存封装在编辑器宿主内部，并在关闭标签/工作区失效时清理；
- `App.tsx` 负责页面级协调和确认对话框，但不直接实现文档状态转移。

### 6.4 确认对话框目标

待确认状态必须携带稳定目标：

```ts
type PendingDocumentAction =
  | { readonly kind: 'close-tab'; readonly tabId: string }
  | { readonly kind: 'switch-workspace'; readonly dirtyTabCount: number }
  | { readonly kind: 'reload'; readonly tabId: string }
  | { readonly kind: 'close-window'; readonly dirtyTabCount: number }
  | { readonly kind: 'mixed-line-endings'; readonly tabId: string };
```

- 确认和取消不得重新查询“当前标签”来决定目标；
- 目标标签已关闭或工作区已失效时，确认动作应安全无操作；
- 同一时刻只允许一个应用内确认流程，后续请求不得覆盖尚未处理的目标；
- 对话框打开时切换标签不会改变确认目标。

## 七、主进程、preload 与安全边界

### 7.1 默认不新增桌面能力

Task 5 应复用：

- `workspace.open()`；
- `workspace.refresh()`；
- `document.readText(relativePath)`；
- `document.saveText(request)`；
- `window.setDirtyState(dirty)`；
- `window.requestClose()`；
- `window.cancelClose()`；
- `window.onCloseRequested(callback)`。

多标签页是 renderer 会话能力，正常实现不需要新增主进程文件系统 API、IPC 通道或 preload 方法。

### 7.2 必须保持的安全属性

- `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`；
- renderer 不直接导入 Node.js、Electron 或文件系统模块；
- preload 不暴露 `ipcRenderer`、通用 `invoke/send/on`、动态通道或任意路径文件能力；
- 保存继续执行 Task 4 的工作区、相对路径、逐段链接、真实路径、普通文件、大小、UTF-8、revision 和安全替换校验；
- 多标签状态不得携带或记录工作区绝对路径、正文日志、临时文件名、文件句柄或原始异常；
- 一个标签的错误不得导致窗口崩溃或其他标签状态丢失。

若实现过程中发现确需修改主进程、preload 或共享契约，必须先在当前工作包记录原因、最小接口、风险与测试；不得仅为方便 renderer 状态管理而扩大桌面权限。

### 8.2 纯状态与不变量测试

- 首个标签、新标签追加和活动标签变化；
- 同一路径去重，包括路径处于 loading 和 error 时；

### 8.3 读取与打开竞态测试

### 8.4 编辑器会话测试

至少覆盖：

- A、B 编辑内容相互独立；
- A 中建立撤销历史，切换 B 编辑后再回 A，A 的撤销仍只作用于 A；
- 标签切换恢复光标和选区；
- 外部正文替换只重建目标标签的编辑器状态；
- 关闭标签清理对应缓存，再次打开从磁盘创建新状态；
- 工作区切换清理全部缓存；
- 切换标签本身不触发 `onContentChange`、不增加修订号和不产生 dirty。

JSDOM 无法可靠断言的 CodeMirror 滚动细节应通过可测试的会话缓存边界和手工桌面验收共同覆盖，不得用脆弱的内部 DOM 选择器伪造通过。

### 8.5 保存与冲突测试

至少覆盖：

- 保存按钮和 `Ctrl+S` 只保存活动标签；
- clean 标签不调用保存 IPC；
- 同一标签重复保存被抑制；
- A、B 可各有一个保存请求在途；
- A 保存结果不改变 B 的正文、状态或 revision；
- A 保存期间继续编辑，旧成功结果不清除 A 的新 dirty；
- 用户切到 B 后 A 保存完成，结果仍提交到 A 且不抢占活动标签；
- 保存失败和冲突只影响目标标签；
- 混合换行确认绑定原标签，切换标签后确认不会保存当前新标签；
- 冲突重新读取绑定原标签，确认后只替换目标标签；
- 工作区失效后的迟到保存结果不更新新会话。

### 8.6 关闭与工作区测试

- clean 标签直接关闭；
- dirty 标签关闭的放弃和取消分支；

### 8.7 手工桌面冒烟验证

7. 保存 A 时切到 B 继续编辑，两个标签最终状态正确；
8. 使用外部编辑器修改 A，A 保存显示冲突，B 仍可正常保存；

## 十二、失败处理与决策规则

- 对不存在或已经关闭的 tabId 的异步结果和确认操作必须安全忽略；
- 发现重复路径时激活既有标签，不合并两份正文或创建第二会话；
- 活动标签不变量被破坏时应在纯状态层阻止提交，不在组件中猜测修复；
- 读取失败只影响目标标签；没有已保存快照时显示错误面板，有快照时保留正文并显示横幅；
- 保存失败不得清除正文、dirty 或已保存 revision；
- 某标签冲突不得阻塞其他标签编辑和保存；
- 用户切换标签后，延迟确认仍作用于原 tabId；目标已失效则无操作；
- saving 标签的破坏性过渡必须被阻止，不声称能够取消已开始的安全替换流程；
- 若 CodeMirror 的公开 API 无法可靠恢复某项视图状态，先记录限制并用最小封装解决，不依赖内部 DOM 或私有字段；
- 若 20 个 5 MiB 标签造成可复现性能问题，应先测量内存与切换耗时，再决定缓存策略，不提前引入虚拟化或后台 worker；
- 若需要改变 Task 4 的 IPC 或安全协议，停止当前工作包并先形成设计说明，未经项目所有者确认不得扩大权限。
