> 本计划记录 Task 9 完成后的系统性界面优化方向。当前阶段只补齐文件管理界面的缺失样式、滚动区域、选择状态与消息展示，不在修复中重构已经通过验收的文件管理流程。

Task 11 进一步纳入了当前主要页面的实际界面观察，以及项目所有者确认的交互方向：取消工作区侧栏底部文件操作按钮区，以右键菜单、键盘入口和文件树内部拖拽承载文件管理；详细范围、安全语义、工作包与验收标准以 Task 11 文档为准。

## 一、目标

在不削弱本地文件安全、稳定标签身份、未保存保护和无障碍语义的前提下，使文枢形成一致、清晰且适合 Windows 桌面使用的视觉与交互体系：

1. 统一颜色、间距、字号、圆角、阴影、焦点与禁用状态；
2. 降低工作区侧栏和文档工具栏的信息密度；
3. 明确区分活动文档、文件管理选择、键盘焦点和悬停状态；
4. 支持不同窗口尺寸以及 Windows 100%/125%/150% 显示缩放；
5. 建立可重复的视觉验收，避免功能完成但样式遗漏。

## 二、规划工作包

### UI-1：设计基线与组件状态

- 建立 CSS 设计变量：基础色、语义色、间距、字号、圆角、阴影和层级；
- 统一按钮、输入框、选择列表、横幅、对话框和空状态；
- 以项目内 SVG 图标替换文件树中的 `F`/`D` 字母占位；
- 完成 hover、active、selected、focus-visible、disabled、loading、success 和 error 状态矩阵；
- 检查文本对比度、键盘焦点和 200% 文本缩放。

### UI-2：工作区侧栏信息架构

- 评估可调整侧栏宽度，并为窄窗口设置合理最小宽度；
- 将高频新建操作与选中项操作分组，减少长期显示的禁用按钮；
- 评估行内更多菜单和右键菜单，同时保留完整键盘入口与可辨识标签；
- 将“另存为当前文档”迁移到文件菜单或文档工具栏，减少文件树职责混杂；
- 改进长路径、深层目录、超长文件名和大量条目下的布局与滚动体验。

### UI-3：编辑区与导航一致性

- 统一 TXT、DOCX 的标签栏、保存状态和错误提示；
- 重整 DOCX 格式工具栏的分组、溢出和窄窗口行为；
- 优化欢迎页、加载、空文档、只读和兼容性提示的视觉层级；
- 统一活动栏、侧栏、编辑区和状态栏的图标、色彩与密度。

### UI-4：反馈与桌面交互

- 成功反馈采用非阻塞、限时且可关闭的 toast；错误和部分完成状态保留可追溯信息；
- 明确危险操作与普通操作的视觉差异，不依赖颜色作为唯一提示；
- 检查对话框焦点圈定、取消后的焦点恢复、键盘顺序和屏幕阅读器名称；
- 验证 Windows 高对比度、系统字体差异和多显示器缩放切换。

### UI-5：视觉质量门禁

- 固定至少 `1280×820`、`900×600` 两种窗口尺寸的截图基线；
- 覆盖空工作区、长文件树、文件管理选择、成功/失败消息、名称输入、目录选择和删除确认；
- 在 Windows 100%、125%、150% 缩放下执行人工验收；
- 把关键页面截图对比加入发布前检查，并保留现有行为测试与完整 `check`/`build` 门禁。

## 三、实施边界

- UI 优化不得改变主进程路径校验、写入安全、回收站删除、revision 冲突和 IPC 权限边界；
- 交互重排必须复用现有 controller，不从展示文本反解析路径或操作身份；
- 任何菜单化或隐藏操作都必须保留键盘访问、明确标签和焦点恢复；
- 视觉测试是现有类型、行为和安全测试的补充，不能替代它们；
- 大范围重构开始前应先形成线框图与状态清单，再拆分为可独立验收的任务。

## 四、完成标准

- 工作区、搜索、TXT、DOCX 和文件管理共享一致的设计语言；
- 常用操作无需依赖偶然换行或滚动到文件树末尾才能发现；
- 所有选择、焦点、禁用、加载、成功与错误状态均可辨识；
- 最小窗口和常见 Windows 缩放比例下无横向溢出、控件遮挡或不可达操作；
- 关键界面具备可重复的截图基线，样式缺失能在发布前被发现。
