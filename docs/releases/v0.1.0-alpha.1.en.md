## Usage

- Portable: verify the SHA-256 hash after downloading, place the executable in a directory
  writable by a standard user, and launch it. It does not install system-level components.
- NSIS: verify the hash, run the installer, and follow the prompts for installation for the
  current user. It does not request elevation by default. Uninstallation removes only the
  application installation content and should not delete an external workspace selected by the user.
- Neither output supports automatic updates. Download fixes manually and verify their hashes again.
- MIT-licensed source code may be made public through GitHub. The portable executable and NSIS
  installer currently remain in the internal Draft only; they are not public downloads, and
  Microsoft Store submission is not planned. Artifact Signing + GitHub OIDC remains optional
  future work if binaries are made public.

## SHA-256 verification

Place both EXE files and `SHA256SUMS.txt` in the same directory, then run each command in PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\WenShu-0.1.0-alpha.1-portable-x64.exe'
Get-FileHash -Algorithm SHA256 -LiteralPath '.\WenShu-0.1.0-alpha.1-setup-x64.exe'
Get-Content -LiteralPath '.\SHA256SUMS.txt'
```

Each filename and its 64-character hexadecimal hash must match the corresponding entry.
Hashes establish only that the downloaded bytes match the checksum file. The current checksum
file and EXE files have no trusted publisher signature, so hashes alone cannot establish a
publicly trusted publisher identity.

## Core features

- Browse, open, and manage TXT/DOCX documents in a local workspace. Deleted files go to the
  Windows Recycle Bin.
- Edit TXT/DOCX documents in multiple tabs, find and replace text, search the workspace, and
  navigate to search results.
- Safe TXT saving and conflict detection; a DOCX intermediate model, compatibility notices,
  validation of saved output, and `.wenshu.bak` backups.
- Protection and close confirmations for unsaved, saving, conflicted, read-only, and degraded states.

## Data and privacy

Document handling is local-first. The application provides no telemetry, crash uploads,
automatic document-content uploads, or cloud sync. Use only synthetic documents when reporting
issues. Do not upload real document content, backups, workspace listings, absolute user paths,
unredacted screenshots or logs, tokens, or certificate material.

## Known limitations

- This is an unsigned internal Alpha for Windows 10 x64. Windows 11 is a possible future
  acceptance target, with no claim of support.
- DOCX support covers only tested features; fully lossless round-tripping of arbitrary complex
  Word documents is not guaranteed.
- No autosave, session recovery, filesystem watching, file associations, automatic updates,
  telemetry, ARM64, ia32, MSI/MSIX, Microsoft Store, macOS, or Linux support.
- Defender and SmartScreen behavior depends on device policies and reputation. Smart App Control
  requires separate acceptance testing if Windows 11 is tested in the future. New files may still
  trigger warnings even if trusted signing is implemented later.
- Subsequent source code in the current repository uses the MIT License (Copyright 2026 Jinxi Hu).
  This tag and the existing Draft predate the `LICENSE` commit. The new license file and new
  outputs must not be retroactively represented as contents of the old tag. See the
  [third-party notices](../../THIRD_PARTY_NOTICES.txt) for third-party components.

## Feedback and downgrading

Report ordinary bugs through GitHub Issues with a minimal, redacted reproduction. Report security
issues privately as described in the [security policy](../../SECURITY.md). When downgrading,
download, verify, and run only a previously retained output that has been explicitly identified
for that purpose. Do not handle an external workspace by rolling back an installer, overwriting
files, or deleting directories. Back up user documents independently before switching application
versions.
