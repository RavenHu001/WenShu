# 文枢测试指南

本文档说明如何验证当前已完成的工程基座、Task 2 工作区能力、Task 3 的 UTF-8 TXT 受控只读读取能力、Task 4 的单 TXT 编辑与安全保存能力，以及 Task 5 的多 TXT 标签页与独立编辑会话能力。现阶段测试目标是确认应用能够安装、检查、构建、选择本地工作区、浏览文件树、从文件树打开多个 TXT 生成独立标签页、在标签间切换并保留各自编辑会话，通过保存按钮或 `Ctrl+S` 安全保存；不包含自动保存、DOCX、工作区搜索或文件管理验收。多标签页实施期间的工作包门禁与最终验收清单见 [TASK-005 规划](./TASK_005_MULTI_TXT_TABS.md)，最终结果以 [TASK-005 完成报告](./TASK_005_COMPLETION_REPORT.md) 为准。

## 1. 前置条件

- Windows 10 或 Windows 11；
- Windows PowerShell 5.1 或更高版本；
- 命令在仓库根目录执行。

首次使用时初始化项目本地 Node.js 和依赖：

```powershell
.\scripts\bootstrap.cmd
.\scripts\npm.cmd ci
```

预期工具版本：

```powershell
.\scripts\node.cmd --version
.\scripts\npm.cmd --version
```

- Node.js：`v22.15.0`；
- npm：`10.9.2`。

下载失败时参见[开发环境说明](./DEVELOPMENT_ENVIRONMENT.md)中的镜像配置和故障处理。

## 2. 自动检查

运行完整质量检查：

```powershell
.\scripts\npm.cmd run check
```

该命令依次验证：

1. Electron 配置、主进程、preload、渲染进程和测试代码的 TypeScript 类型；
2. ESLint 静态检查；
3. Prettier 格式检查；
4. Vitest 单元测试。

验收标准：命令退出码为 `0`，没有 TypeScript、ESLint 或格式错误，全部测试通过。

需要单独定位问题时，可以分别运行：

```powershell
.\scripts\npm.cmd run typecheck
.\scripts\npm.cmd run lint
.\scripts\npm.cmd run format:check
.\scripts\npm.cmd test
```

### 2.1 Task 4 实施前基线门禁

Task 4 将首次引入用户文件写入，因此开始实现前必须确认：

- Windows 检出环境中的换行策略明确，`format:check` 可重复通过；
- Vitest worker、临时目录和符号链接能力探测不会导致整个测试文件超时或跳过；
- 不支持真实 symlink/junction 的环境只条件跳过对应少量集成用例，并由 mock 测试确定性覆盖拒绝分支；
- Task 2、Task 3 的测试实际执行并通过；
- `check` 与 `build` 不并行运行且均通过。

2026-08-04 的一次 Windows 受控环境检查发现 Prettier 行尾差异和 Vitest worker / 初始化超时。它们必须在 Task 4 WP0 中复现、归因并处理，不能通过删除测试、整文件跳过或单纯增加超时掩盖。

### 2.2 Task 5 实施前基线门禁

Task 5 将把单文档 renderer 状态扩展为多标签会话，但不应改变 Task 4 的文件系统权限和安全保存协议。开始实现前必须确认：

- `main` 已包含 Task 4，工作树修改已识别并受到保护；
- 当前 `check` 与 `build` 依次执行并通过；
- TXT 读取、保存、IPC、preload、工作区组件和窗口关闭测试均实际执行；
- 单标签编辑、保存期间继续输入、冲突、混合换行和未保存保护行为可重复；
- Task 5 每个工作包继续运行完整 `check` 和 `build`，不得用新多标签测试替代既有安全回归。

2026-08-06 的规划基线为：9 个测试文件通过，224 个用例通过，2 个真实符号链接用例因本机权限条件跳过，生产构建通过。实现中的实际结果应记录在各工作包报告中，最终以 `TASK_005_COMPLETION_REPORT.md` 为准。

```powershell

```

- 标题和中央欢迎区域显示“文枢”；
- 顶部菜单占位、左侧活动栏、工作区侧栏、中央欢迎区域和底部状态栏均可见；
- 状态栏显示 `Windows · Electron <版本>`；
- 尚未打开工作区时显示“尚未打开文件夹”和“打开文件夹”入口；
- 点击“打开文件夹”会打开原生目录选择器；
- 取消选择不会报错或清除已经打开的工作区；
- 成功选择后显示工作区名称、路径和文件树；

- 点击“刷新”后可以看到外部增加或删除的文件；

- 关闭窗口后应用正常退出。

### 3.1 TXT 读取与编辑验收

准备一个包含多层目录的测试文件夹，并在根目录与子目录中各放置一个 UTF-8 TXT（建议包含中文、多行和空白），另准备一个空 TXT、一个非 TXT 文件和一个超过 5 MiB 的 TXT。

- 点击根目录 TXT：中央区域先显示"正在读取 <文件名>…"，随后显示以文件名命名的单个活动标签和可编辑正文；
- 正文可用 CodeMirror 编辑：输入、删除、复制粘贴、撤销和重做均生效；
- 展开子目录并打开嵌套 TXT，内容正确且标签标题为文件名；
- 打开空 TXT：标签正常显示，正文区域为空且可输入；
- 连续快速选择两个 TXT：生成两个标签，最后选择的为活动标签（多标签语义见 3.3）；
- 点击非 TXT 文件、目录或符号链接：不读取正文，中央区域内容不变；
- 删除一个尚未打开的 TXT 后点击它：显示错误提示，应用不崩溃；
- 打开超过 5 MiB 或非 UTF-8 编码的 TXT：显示明确错误提示，不显示部分正文；
- 已有正文时打开失败文件：原正文保留并显示非阻塞错误横幅；
- 点击"刷新"：当前编辑正文保持可见；
- 成功切换工作区：旧正文清除并回到欢迎状态；
- 取消切换工作区：旧正文保留；
- 开发者控制台没有未处理异常；
- 测试过程中确认应用没有创建、修改或删除任何测试文件（保存用例除外）。

### 3.2 编辑与保存验收

- 首次修改后标签出现未保存标记（●），工具条显示"未保存"；
- 点击"保存"与按 `Ctrl+S` 发起同一保存流程；未修改时保存不触发写入；
- 保存期间显示"正在保存…"，快速重复保存不会并发写入；
- 保存成功且期间无新编辑：未保存标记消失，显示"已保存"；
- 保存期间继续编辑：旧保存成功后未保存标记仍存在，再次保存基于新版本；
- 保存失败（只读文件、权限错误等）：正文与未保存标记保留，显示"保存失败"；
- 用其他编辑器（如记事本）修改已打开文件后再保存：显示"外部冲突"，外部内容未被覆盖，本地正文保留；点击"重新读取"并确认后载入磁盘版本；
- BOM 文件保存后 BOM 保留；LF 与 CRLF 文件保存后换行风格不变；
- 混合换行文件保存：先弹出"确认换行规范化"对话框，确认后才按主要换行风格统一保存；
- 有未保存修改时关闭标签 / 切换工作区 / 关闭窗口：分别验证"放弃修改"与"取消"分支，取消后正文、文件、工作区和选择状态全部保留；
- 保存后继续输入，确认未保存标记重新出现；
- 刷新工作区后当前编辑内容保持；
- 工作区目录中没有遗留 `.wenshu-*` 临时文件。

### 3.3 多标签页与独立会话验收

- 从文件树连续打开三个不同目录的 TXT：标签顺序与点击顺序一致，最后打开的标签为活动标签；
- 重复点击已打开文件只激活原标签，不重复读取、不重置正文；
- 打开两个同名不同路径的文件：两个标签并存，`title` 提示可区分完整路径；
- 在不同标签中输入不同内容并来回切换：正文与未保存标记各自独立、互不污染；
- 每个标签的光标、选区、滚动位置和撤销历史独立；普通切换不清空历史、不产生未保存标记；
- 保存一个标签不会清除其他标签的未保存标记；保存 A 时切到 B 继续编辑，两个标签最终状态正确；
- 用其他编辑器修改 A 后保存：A 显示外部冲突，B 仍可正常编辑和保存；
- 关闭 clean 标签无需确认；关闭 dirty 标签需"放弃修改/取消"确认；关闭按钮与 `Ctrl+W` 行为一致；
- 关闭活动标签后优先激活右侧标签，没有右侧时激活左侧；关闭最后一个标签回到欢迎页；
- 有多个 dirty 标签时切换工作区与关闭窗口：确认文案包含未保存标签数量，分别验证放弃与取消分支；
- 正在保存的标签无法被关闭、随工作区切换或窗口关闭丢弃，界面提示等待保存完成；
- 刷新文件树不影响已打开标签；
- 连续打开接近 20 个普通 TXT：标签栏可横向滚动，切换无明显等待；
- 开发者控制台与启动终端没有未处理异常、正文、绝对路径或临时文件名日志。

当前不应出现自动保存、文档管理或工作区搜索功能。

## 5. 安全边界检查

当前阶段应持续满足：

- `BrowserWindow` 使用 `nodeIntegration: false`；
- `contextIsolation: true`；
- sandbox 保持启用；
- preload 只暴露只读运行环境数据、固定的 `workspace.open()` / `workspace.refresh()`、`document.readText(relativePath)` / `document.saveText(request)` 以及 `window` 关闭协调窄协议（`setDirtyState` / `requestClose` / `cancelClose` / `onCloseRequested`）；
- 渲染进程不直接导入 Node.js 文件系统 API；
- 不向渲染进程暴露 `ipcRenderer` 或通用 IPC 调用器；
- 工作区 IPC 不接受渲染进程提供的绝对路径；
- `document.readText` 与 `document.saveText` 只接受文件树快照中的规范相对路径，主进程对其重新执行格式、边界、符号链接、类型、大小与 UTF-8 校验；
- 文档读取只使用只读文件系统 API（`lstat`、`realpath`、有界 `read`）；
- TXT 保存执行：工作区与路径重校验、SHA-256 内容版本冲突检测（不一致返回 `CONFLICT` 且不写盘）、同目录排他临时文件、完整写入、`sync` 刷盘、关闭与同文件系统 `rename` 替换；失败时原文件不删除不截断并尽力清理临时文件；
- 保存 IPC 入口拒绝多余危险字段（工作区根、绝对目标、临时路径、编码、替换策略等）并对参数执行运行时校验；
- 窗口关闭协调不获得文件内容、工作区根路径或通用 IPC 能力；
- 跨进程结果不包含原始异常、Buffer、文件句柄或调用栈。

这些约束主要由代码审查、类型隔离、单元测试和真实窗口启动共同验证。后续新增桌面能力时，应为每个具体用例设计独立接口和测试。

## 6. 推荐验收顺序

```powershell
.\scripts\bootstrap.cmd
.\scripts\npm.cmd ci
.\scripts\npm.cmd run check
.\scripts\npm.cmd run build
.\scripts\dev.cmd
```

不要并行运行 `check` 和 `build`：electron-vite 构建期间会创建临时配置文件，与 ESLint 扫描并发时可能产生无意义的文件竞争。
