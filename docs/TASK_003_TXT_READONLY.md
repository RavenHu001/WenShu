## 一、任务目的

Task 2 已建立“选择工作区 → 主进程扫描目录 → 受控 IPC 返回快照 → React 文件树展示”的只读工作区链路，但普通文件节点仍不可选择，应用也不会读取文件正文。

本任务实现第二个产品纵向切片：用户从文件树选择一个工作区内的 UTF-8 TXT 普通文件，主进程在当前工作区授权边界内校验并读取正文，渲染进程在中央区域的单个只读标签页中显示内容。

该切片必须贯通以下链路：

```text
React 文件树选择 TXT 相对路径
  -> 受限 preload API
  -> 固定 document:read-text IPC 通道
  -> 主进程读取当前工作区状态
  -> 路径、类型、符号链接、大小与 UTF-8 校验
  -> 可序列化的只读文档快照
  -> React 中央区域单标签显示
```

本任务的核心目标是验证“文件树选择 → 受控文件读取 → 中央区域显示”的安全链路。它不提供编辑、保存或真正的多标签页能力。

## 二、完成后的用户体验

任务完成后，用户应能：

1. 打开一个包含 TXT 文件的本地工作区；
2. 通过鼠标或键盘选择普通 `.txt` 文件；
3. 在读取期间看到明确的加载状态；
4. 在中央区域看到以文件名命名的单个只读标签页；
5. 阅读 UTF-8 中文、英文、换行和空白内容；
6. 正常打开空 TXT 文件；
7. 选择另一个 TXT 文件，用新内容替换当前单标签内容；
8. 在读取失败、文件过大或编码非法时看到可恢复的错误提示；
9. 在成功切换工作区后回到未选择文档状态；
10. 在取消工作区切换或工作区刷新时保留当前只读文档快照。

非 TXT 文件、目录、符号链接和其他类型节点在本任务中不得读取正文。界面可以保持其只读展示，也可以提供简短的“不支持打开”提示，但不得调用通用文件读取能力。

## 四、固定设计决策

### 4.1 单个只读文档快照

- 每次成功读取返回一次性、不可变、可序列化的文档快照；
- 中央区域最多显示一个 TXT 标签页；
- 再次选择 TXT 文件直接替换当前标签，不维护标签数组；
- 标签页不提供关闭按钮、未保存标记或恢复状态；
- 正文只读，允许浏览器原生选择和复制；
- 不引入 CodeMirror、Monaco、Zustand 或其他编辑器、状态管理依赖。

此设计只验证文档读取链路，不提前实现多标签页和编辑器架构。后续任务可以在稳定契约之上扩展，而不应要求本任务预建完整编辑器系统。

### 4.2 相对路径是受控标识，不是授权

- 渲染进程只能提交文件树快照中的规范工作区相对路径；
- 相对路径使用 `/` 分隔，不得为空，不得包含空段、`.`、`..`、反斜杠或空字符；
- 主进程必须把所有 IPC 输入视为不可信数据并重新验证；
- 主进程不得接受渲染进程传入的工作区根路径或任意绝对路径；
- 文件是否显示在旧快照中不能代替主进程的实时路径、类型和边界检查。

Task 2 中“`relativePath` 不得触发文件系统读取”的约束在本任务后调整为：只有新的固定 TXT 读取用例可以使用相对路径，并且必须经过本任务规定的主进程校验。

### 4.3 TXT 范围、编码与大小

- 只接受扩展名大小写不敏感的 `.txt` 普通文件；
- 文件内容必须是合法 UTF-8；
- 可接受 UTF-8 BOM，但返回正文时不应把 BOM 显示为字符；
- 不自动猜测、转换或回写 GBK、UTF-16 等其他编码；
- 保留原始换行和正文字符，不进行格式转换；
- 单文件最大允许读取 `5 MiB`（`5 * 1024 * 1024` 字节）；
- 超过上限返回明确错误，不截断读取，也不把部分正文传给渲染进程。

固定大小上限用于保护主进程、IPC 和渲染进程内存。若后续需要支持更大文件，应基于实测单独设计流式读取或虚拟化，不在本任务中扩展。

### 4.4 工作区与文档状态协调

- 当前工作区根路径继续由主进程持有；
- 文档读取开始时捕获当前工作区根路径，本次读取只使用该快照；
- 成功切换工作区后清除渲染进程中的旧文档；
- 取消或打开新工作区失败时保留旧工作区和旧文档；
- 手动刷新工作区只替换文件树快照，不自动重新读取或清除当前文档；
- 若刷新后文件已被删除，当前只读正文仍作为最后一次成功读取的快照显示，重新选择时再报告错误；
- 多次读取请求可能乱序完成，界面必须只接受最近一次用户选择对应的结果；
- 工作区成功切换时也必须使旧工作区尚未完成的读取结果失效。

不在本任务中加入文件监听、自动刷新、请求取消协议或持久化状态。

## 五、共享数据契约

建议新增 `src/shared/document.ts`，只包含纯 TypeScript 类型和常量，不依赖 Electron、Node.js、React 或浏览器运行时。

推荐采用以下语义等价契约：

```ts
export interface TextDocumentSnapshot {
  readonly name: string;
  readonly relativePath: string;
  readonly content: string;
  readonly byteLength: number;
}

export type TextDocumentErrorCode =
  | 'NO_WORKSPACE'
  | 'INVALID_PATH'
  | 'OUTSIDE_WORKSPACE'
  | 'UNSUPPORTED_TYPE'
  | 'NOT_FILE'
  | 'NOT_FOUND'
  | 'ACCESS_DENIED'
  | 'TOO_LARGE'
  | 'INVALID_UTF8'
  | 'READ_FAILED';

export interface TextDocumentError {
  readonly code: TextDocumentErrorCode;
  readonly message: string;
}

export type ReadTextDocumentResult =
  | { readonly status: 'loaded'; readonly document: TextDocumentSnapshot }
  | { readonly status: 'error'; readonly error: TextDocumentError };
```

契约要求：

- 所有字段均为只读；
- 所有返回值必须能被 Electron structured clone 安全复制；
- 不传递 `Error`、`Buffer`、文件句柄、`Stats`、函数或类实例；
- `name` 由主进程从最终文件路径取得，不信任渲染进程提供的名称；
- `relativePath` 返回经过验证的规范相对路径；
- `byteLength` 表示原始文件字节数，不表示 JavaScript 字符串长度；
- 错误消息不得包含文件正文、调用栈或不必要的系统内部信息；
- 错误码供界面稳定分支，消息供用户理解，不应依赖字符串匹配控制逻辑。

`src/shared/desktop-api.ts` 应扩展为：

```ts
interface DesktopApi {
  readonly runtime: DesktopRuntimeInfo;
  readonly workspace: {
    readonly open: () => Promise<OpenWorkspaceResult>;
    readonly refresh: () => Promise<RefreshWorkspaceResult>;
  };
  readonly document: {
    readonly readText: (relativePath: string) => Promise<ReadTextDocumentResult>;
  };
}
```

## 六、主进程实现要求

### 6.1 工作区会话状态

当前工作区根路径不应继续只作为 `workspace-ipc.ts` 内无法共享的局部变量。建议抽出最小会话模块：

```text
src/main/workspace/
├─ scan-workspace.ts
├─ workspace-ipc.ts
└─ workspace-session.ts
```

该模块只负责：

- 获取当前工作区根路径；
- 在工作区成功打开并扫描后更新根路径；
- 保持失败或取消时不修改根路径。

不得借此引入通用状态容器、持久化、最近工作区、多窗口会话或可由渲染进程直接修改的状态接口。

如果实现者选择向文档 IPC 注入只读的 `getCurrentWorkspaceRoot` 函数，也可以接受，但必须保持同等测试性、安全边界和单一状态来源。

### 6.2 TXT 读取器

建议结构：

```text
src/main/document/
├─ read-text-document.ts
└─ document-ipc.ts
```

读取器应按以下顺序完成验证：

1. 确认已打开工作区；
2. 确认输入是符合第 4.2 节格式的非空相对路径；
3. 确认扩展名为 `.txt`；
4. 以当前工作区根路径解析候选路径；
5. 使用 `path.relative` 等语义等价检查拒绝词法路径逃逸；
6. 从工作区根目录开始逐段检查候选路径，拒绝任一层符号链接或 junction，并确认中间段为目录、最终段为普通文件；
7. 获取工作区根路径和候选文件的真实路径；
8. 再次确认真实文件路径位于真实工作区根目录内；
9. 在读取正文前检查文件大小不超过 5 MiB；
10. 以最多 `5 MiB + 1 byte` 的有界方式异步读取，避免文件在预检查后增长导致无界内存分配；
11. 再次确认实际长度不超过上限；
12. 使用 fatal 模式严格解码 UTF-8；
13. 返回文档快照，或把失败映射为稳定错误码。

实现必须：

- 使用 `node:fs/promises` 异步 API；
- 对 Windows 路径大小写和分隔符使用 Node.js `path` 语义处理；
- 将 `ENOENT`、`EACCES`、`EPERM` 等常见错误映射为稳定错误码；
- 捕获文件在校验与读取之间被外部删除或替换的情况，不让 IPC 拒绝；
- 不在大小预检查后对可能增长的文件执行无界 `readFile`；
- 不记录正文，不把正文写入日志；
- 不调用任何写入、创建、重命名、删除或权限修改 API；
- 不建立通用文件处理器注册表或依赖注入容器。

静态符号链接和 junction 逃逸必须防护。对于本地进程恶意并发替换文件导致的操作系统级 TOCTOU 竞态，本任务要求尽量缩小校验与读取窗口并保证只读，不要求实现平台原生句柄级防竞态方案；该限制应记录在完成报告中。

### 6.3 IPC 注册

只注册一个新的固定请求/响应通道：

- `document:read-text`

要求：

- 使用 `ipcMain.handle`；
- 只接受一个字符串相对路径参数；
- 在处理器入口验证参数数量和类型；
- 不接受根路径、编码、大小限制或任意选项参数；
- 在处理器开始时读取并捕获当前工作区根路径；
- 所有预期与意外失败都转换为 `ReadTextDocumentResult`；
- 不注册 `file:read`、`fs:*`、通用命令分发或动态通道代理；
- 保持 IPC 注册幂等，避免重复注册处理器。

## 七、preload 与渲染进程边界

### 7.1 preload API

preload 只新增以下闭包接口：

```ts
document: Object.freeze({
  readText: (relativePath: string) => ipcRenderer.invoke('document:read-text', relativePath),
});
```

必须继续禁止暴露：

- `ipcRenderer`；
- 通用 `invoke(channel, ...args)`；
- 任意绝对路径读取；
- 编码、文件大小限制或 Node.js 选项控制；
- Node.js `fs`、`path`、`process` 或 Electron 对象。

`DesktopApi` 及 `window.desktop` 全局类型必须同步更新，主进程、preload 和渲染进程使用同一共享结果契约。

### 7.2 文件树交互

`FileTreeNode`、`FileTree` 与 `WorkspaceSidebar` 应增加最小、明确的回调传递：

- 普通 `.txt` 文件节点渲染为可访问按钮；
- 点击或通过键盘激活时传递该节点的 `relativePath`；
- 当前选中文件具有可辨识的选中状态；
- 读取期间暂时高亮本次请求的 TXT；若读取失败且保留了上一个成功文档，则选中状态恢复到上一个文档；
- 非 TXT 文件、符号链接、目录和其他节点不调用 `document.readText`；
- 文件树组件只报告用户意图，不直接调用 preload API；
- 目录原有展开、折叠、空状态和局部错误行为保持不变。

扩展名判断只决定界面交互，不能替代主进程校验。

### 7.3 中央只读文档区

建议新增：

```text
src/renderer/components/document/
├─ DocumentPane.tsx
└─ ReadonlyTextDocument.tsx
```

中央区域至少表达以下状态：

- `welcome`：尚未选择文档，显示现有欢迎内容；
- `loading`：显示正在读取的文件名和加载状态；
- `loaded`：显示一个活动标签及只读正文；
- `error`：显示可理解、可恢复的读取错误。

正文可以使用只读 `<textarea>` 或能保留空白与换行的等价语义元素。必须：

- 明确设置只读；
- 保留换行和空白；
- 支持原生选择与复制；
- 不使用 `contentEditable` 模拟只读；
- 不把正文注入 `innerHTML`；
- 空文件仍显示已打开标签和空正文区域；
- 中央区域继续占据布局主体。

读取失败时，如果已有成功文档，应保留原正文并显示非阻塞错误提示；如果尚无成功文档，则显示错误面板。新的成功读取应清除旧错误。

### 7.4 React 状态与异步竞态

本任务继续使用 React 自带状态能力。建议由 `App` 或一个小型文档容器持有当前文档状态，通过 props 向工作区侧栏传递：

- `onTextFileOpen(relativePath)`；
- `selectedTextFilePath`；
- `onWorkspaceSelected(workspace)` 或语义等价的成功切换通知。

工作区侧栏可继续持有现有扫描状态，不要求把全部工作区状态提升或引入 Context。

异步读取必须使用递增请求编号、当前请求 token 或语义等价机制，保证：

- 先点 A、后点 B，即使 A 最后返回，也只能显示 B；
- 切换工作区后，旧工作区未完成的读取结果不能重新出现；
- IPC Promise 意外拒绝会转换为界面错误，不产生未处理 rejection；
- 组件卸载后不继续提交过期结果。

## 十二、失败处理与决策规则

- 若未打开工作区，返回 `NO_WORKSPACE`，不尝试使用渲染进程提供的根路径；
- 若路径格式非法或逃逸工作区，返回稳定拒绝结果，不规范化后“尽量读取”；
- 若目标不是普通 TXT 文件，拒绝读取，不降级为任意文本预览；
- 若文件超过 5 MiB，拒绝全部正文，不截断显示；
- 若 UTF-8 非法，返回编码错误，不使用替换字符静默解码；
- 若文件在读取期间被外部修改、替换或删除，转换为可恢复错误，不重试循环；
- 若新读取失败且已有成功文档，保留原快照并显示错误；
- 若读取请求乱序完成，丢弃过期界面结果，不把它视为用户错误；
- 若 Windows 符号链接测试需要管理员权限，使用 mock 或纯逻辑测试，不提升权限；
- 若需要改变 5 MiB 上限、UTF-8-only、单标签或只读边界，应停止相关实现并向项目所有者说明收益、风险、复杂度和迁移成本；
- 不得删除有效测试、降低 Electron 安全设置、关闭严格类型检查或忽略 lint 规则来制造通过结果。
