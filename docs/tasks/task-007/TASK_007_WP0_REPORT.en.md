## 3. Test reliability: React 19 `act` diagnosis and fix (section 3.2 gate)

### 3.1 Reproduction

The first `tests/search/result-locate.test.tsx` case reproduced Task 6's known one-off stderr warning:
"A component suspended inside an `act` scope, but the `act` call was not awaited."

### 3.2 Cause (temporary instrumentation of `act`/`flushActQueue` in `react.development.js` and RTL `act-compat`)

1. Trigger: RTL `eventWrapper` uses **synchronous** `act`, which is never awaited. When `flushActQueue` is skipped because `isFlushing` is true, entries remain in the act queue and schedule this one-off warning.
2. Source: `prepareDocument` in `@testing-library/user-event@14.6.1` installs a **capture-phase blur listener** on `document`. Blurring an input whose value changed dispatches another `change` via `dispatchDOMEvent`. Dispatch during the previous act flush (`isFlushing=true`) triggers the warning.
3. Scenario: `submitSearch` enters a query using `user.type` + `user.keyboard('{Enter}')`; `clickMatch` opens/navigates to a tab, and editor focus blurs the search input, triggering the blur→change dispatch.

### 3.3 Fix

`submitSearch` in `result-locate.test.tsx` now uses an equivalent `fireEvent` sequence: click Search → `change` input value → keyDown Enter → form submit. Query submission and state transitions remain the tested behavior, while the user-event document capture-dispatch path is removed. All 12 original assertions pass. Typing semantics remain covered by `tests/search/search-sidebar.test.tsx`, which retains user-event. The full test suite no longer emits the warning.

### 3.4 Resolution record

- Junction-cleanup `EBUSY` did not reproduce. All 49 reader tests ran, with 2 real-link cases skipped for local permission conditions, matching the planned baseline; lstat mocks deterministically cover rejection.
- No tests were deleted, whole files skipped, assertions weakened, or timeouts extended to manufacture a passing baseline.

### 4.1 Failure-sample observations

- Damaged ZIP/disguised extension: Mammoth throws "Can't find end of central directory", a stable error.
- Missing `word/document.xml`, including the encrypted-layout simulation: "Could not find main document part".
- Oversized sample: the ZIP reader ignores trailing padding and still parses; **check file size before ZIP parsing**. WP2 order: size → ZIP structure/budgets → Mammoth import.
- No network external relationships are read (`externalFileAccess: false` by default), and no document content is executed.

### 4.2 Fixed WP2 importer requirements

1. Use the document model from `mammoth.convertToHtml({buffer}, {transformDocument})` as the semantic import source. Options are the **second argument**: Mammoth 1.12.1 measurements confirmed that transformDocument in the first argument is ignored.
2. JSZip performs only three limited supplements: per-run `w:color` extraction, existence of `word/header*.xml`/`word/footer*.xml`, and existence of `w:ins`/`w:del` in document.xml. It parses no other OOXML attributes.
3. Freeze warning sources: images/tables/comments/hyperlinks from Mammoth; headers/footers/tracked changes from JSZip inspection.

## 5. Minimum Tiptap / ProseMirror schema and export mapping (section 3.4 findings 3/4)

### 5.1 Extension chain (measured without duplicate warnings)

```ts
StarterKit.configure({ heading: { levels: [1, 2, 3] } })  // v3 已含 underline、bold、italic、列表、历史等
+ TextStyle + Color + FontSize（@tiptap/extension-text-style 的 FontSize）
+ TextAlign.configure({ types: ['heading', 'paragraph'] })
```

- `getSchema` works in Node without DOM. The schema has 11 nodes including paragraph, heading, bulletList, orderedList, listItem, doc, and text. Marks include bold, italic, underline (built into StarterKit v3; duplicate registration triggers "Duplicate extension names"), textStyle, link, code, and strike.
- color/fontSize are textStyle attrs (`{color, fontSize}`, null by default; fontSize is an `'18px'` string).
- JSON round-trip through `schema.nodeFromJSON` → `node.toJSON()` works. Materialized defaults (color:null, textAlign:null) make strings differ while semantics stay equal; normalization is a recorded WP1 conversion requirement.
- StarterKit includes link by default. Because hyperlinks degrade to visible text, WP5 will decide to disable link input with `StarterKit.configure({ link: false })`, recorded as a WP5 decision.

### 5.2 `docx` export mapping (XML-level measurements)

`docx@9.7.1` export of MiniModel was verified: headings → `w:pStyle w:val="HeadingN"`; bold/italic/underline → `w:b`/`w:i`/`w:u w:val="single"`; sizes → `w:sz` in half-points; colors → `w:color w:val="RRGGBB"`; alignment → `w:jc`; bullets/numbering → `w:numPr`, with `numbering.config` generating numbering.xml. Measured levels 0/1 reimport into Mammoth as `{isOrdered, level}`.
The minimum round-trip **Mammoth import → MiniModel → `docx` export → Mammoth reimport** preserves body, headings, marks, sizes, alignment, and list semantics. JSZip supplements colors, absent from Mammoth's model.

## 11. Unresolved issues and known limitations

1. **Nondeterministic docx@9 output**: core.xml timestamps use current time (`TimestampElement` uses `new Date()`), so two saves necessarily differ in bytes. Actual-byte revisions are unaffected; the saver needs no deterministic output.
2. **Mammoth omits colors/headers/footers/tracked changes**: these three information categories require limited JSZip supplements (section 4). WP2 follows the fixed order and reads only necessary attributes.
3. **No actual Office-encrypted fixture constructed**: `fail-encrypted-sim` only reproduces the part layout. WP2 covers “missing critical parts → stable rejection”; WP7 uses a real encrypted file for final verification.
4. **External Office environment confirmed**: Microsoft Word 16.0.20228.20158 (`C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE`); actual round-trip smoke remains scheduled for WP7.
5. **Pre-existing audit alerts**: pinned Electron 37 and eslint-toolchain brace-expansion were not introduced here.
6. **Tiptap materializes default schema attributes**: model↔Tiptap JSON requires normalization in WP1.
7. **StarterKit includes link/blockquote by default**: schema is slightly broader than the supported matrix. WP5 decides whether to trim it with `link: false` and similar options; this does not block WP0.
