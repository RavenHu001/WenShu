## 1. 状态与背景

> **状态：已完成。代码实现与自动验收于 2026-08-22 完成；Windows 物理显示缩放等最终人工验收于 2026-08-27 由项目所有者确认通过。**
>
> WP0-WP5 已按顺序实施；技术冻结见 [TASK-011 WP0 报告](./TASK_011_WP0_REPORT.md)，
> 实现、测试、截图与验收差异见 [TASK-011 完成报告](./TASK_011_COMPLETION_REPORT.md)。

开发时可直接使用配套的 [TASK-011 开发提示词](./TASK_011_DEVELOPMENT_PROMPT.md)。

Task 1 至 Task 10 已完成工作区、TXT/DOCX 编辑、安全保存、搜索、查找替换和基础文件管理闭环。当前功能与安全能力已经能够支撑日常验证，但界面仍具有明显的工程原型特征：顶部存在原生与应用内双菜单，工作区侧栏底部长期展示大面积文件操作按钮，文件树使用字母占位图标，DOCX 工具栏缺少分组和窄窗口策略，编辑区、标签、保存状态、搜索结果和状态栏尚未形成一致的桌面交互体系。

本任务把既有《未来 UI 优化计划》落实为可开发、可测试、可验收的阶段任务。任务不改变文件系统权限、安全写入、revision 冲突、备份、稳定 tabId、搜索失效和未保存保护等既有语义。

## 2. 阶段目标

在不削弱现有功能、安全和无障碍语义的前提下，使文枢从“功能完整的工程原型”进入“适合长期日常使用的 Windows Pre-alpha 产品”阶段：

1. 建立统一的颜色、间距、字号、图标、焦点和组件状态体系；
2. 消除重复菜单和长期占位界面，明确应用外壳的信息层级；
3. 取消工作区侧栏底部的文件操作按钮墙，以右键菜单、键盘和文件树内部拖拽承载文件操作；
4. 提升文件树可用空间，支持侧栏调整宽度、折叠和长路径场景；
5. 统一 TXT、DOCX、工作区搜索和当前查找的导航、状态与反馈；
6. 优化 DOCX 内容列宽和工具栏分组，但不模拟精确 Word 分页；
7. 建立固定窗口尺寸与 Windows 缩放比例下可重复执行的视觉质量门禁。

## 3. 设计原则

### 3.1 操作与对象就近

- 文件和文件夹操作放在文件树对象的右键菜单中；
- 新建操作放在目标目录或文件树空白区域的右键菜单中；
- 文档级操作放在标签、文件菜单或编辑区中；
- 不在侧栏底部长期展示所有可能操作。

### 3.2 高频操作直接，低频操作收纳

- 打开工作区、刷新、新建等高频操作保留可发现入口；
- 重命名、移动、删除、在资源管理器中显示等选中项操作进入上下文菜单；
- 另存为属于当前文档，不属于文件树批量管理。

### 3.3 鼠标效率不能替代键盘与无障碍

- 右键菜单和拖拽必须有键盘等价入口；
- 菜单项必须有明确文字，不依赖图标猜测；
- 选择、活动、焦点和悬停必须是四种可区分状态；
- 危险操作不得只依赖红色表达。

### 3.4 复用既有安全服务

- UI 不自行拼接或反解析文件路径；
- 右键菜单、键盘命令和拖拽移动必须调用既有 controller；
- 不新增通用文件系统 IPC，不暴露任意路径或 overwrite/force 开关；
- UI 预判仅用于即时反馈，主进程仍是最终安全裁决者。

## 4. 目标信息架构

```text
┌ 单一标题栏 / 菜单 ─────────────────────────────────────┐
├ 活动栏 ┬ 可调侧栏 ┬ 标签栏                              │
│        │          ├ 紧凑文档状态 / 文档工具栏           │
│ 文件   │ 文件树   │                                     │
│ 搜索   │ 或搜索   │        DOCX 居中内容画布             │
│ 设置   │          │        或 TXT 编辑器                 │
│        │          │                                     │
├────────┴──────────┴─────────────────────────────────────┤
│ 简洁状态栏：保存状态、文档类型、字数/字符数等           │
└─────────────────────────────────────────────────────────┘
```

### 4.1 顶部与菜单

- 原生菜单与应用内菜单只能保留一套，不再同时显示英文原生菜单和中文应用菜单；
- 菜单语言与应用语言一致；
- 文件菜单承载打开工作区、新建、保存、另存为、关闭标签等文档级命令；
- 编辑、视图、帮助菜单只展示已经实现且可工作的入口，不保留无行为占位项；
- 运行时版本信息移入“关于”，不长期占据状态栏。

### 4.2 活动栏

- 使用项目内 SVG 图标替换“文 / 搜 / 设”文字占位；
- 每个图标提供 tooltip 和无障碍名称；
- 未实现的设置入口在功能实现前不伪装成可用功能；
- 活动状态同时使用形状、背景和语义属性表达，不只改变颜色。

### 4.3 工作区侧栏

- 支持在合理最小值和最大值之间拖动调整宽度；
- 支持折叠并能通过键盘或菜单恢复；
- 工作区标题区保留打开工作区、刷新和紧凑的新建入口；
- 文件树成为主要滚动区域，不再被底部按钮区持续挤压；
- 长文件名提供省略、完整 tooltip 和稳定缩进；
- 深层目录、大量条目和窄窗口下不得产生不可达操作。

### 4.4 标签、文档状态与编辑区

- 标签同时表达活动、dirty、saving、错误和关闭能力；
- 活动标签不能只依靠顶部一条细线识别；
- 保存按钮只在可执行时具有强调权重；
- 已保存、正在保存、保存失败、冲突和备份信息使用紧凑状态区域；
- 详细备份路径放入 tooltip、详情或通知，不长期占据整行；
- DOCX 使用居中、有限最大宽度的内容画布，外围为工作区背景；
- DOCX 内容画布只是阅读列宽与视觉层级，不承诺精确分页；
- TXT 保持适合纯文本编辑的全高编辑器布局。

### 4.5 DOCX 工具栏

- 按“历史、字符格式、段落样式、列表与对齐”分组；
- 使用统一图标、tooltip、激活状态和分隔关系；
- 窄窗口下按固定优先级进入溢出菜单，不允许横向把编辑区撑开；
- 颜色选择同时显示当前值和可访问名称；
- 所有命令继续使用 Tiptap/ProseMirror 公开 API。

### 4.6 搜索与当前查找

- 工作区搜索和当前查找保留不同语义，但共享输入框、按钮、反馈和焦点样式；
- 搜索结果以“文件标题 → 命中条目”建立清晰层级；
- 匹配片段是主体，行列号和文件类型是次级信息；
- 搜索说明默认简化，详细限制可通过帮助入口查看；
- 侧栏调整宽度后，结果片段应自然获得更多空间；
- 查找匹配、当前匹配、输入焦点和按钮焦点使用不同且一致的视觉语义。

### 4.7 状态栏与反馈

- 状态栏降低高度和色彩权重；
- Electron 版本移至“关于”；
- 成功操作使用非阻塞、限时、可关闭的 toast；
- 错误、冲突和部分完成状态保留可追溯信息，不自动消失；
- 危险操作使用图标、文字、位置和颜色共同表达风险。

## 5. 文件树右键菜单

### 5.1 工作区根或空白区域

建议菜单顺序：

1. 新建 TXT；
2. 新建 DOCX；
3. 新建文件夹；
4. 分隔线；
5. 刷新；
6. 在资源管理器中显示工作区。

### 5.2 普通文件

建议菜单顺序：

1. 打开或激活；
2. 重命名；
3. 移动到；
4. 在资源管理器中显示；
5. 分隔线；
6. 删除到回收站。

对于当前文档，可在标签右键菜单和文件菜单中提供“保存”“另存为”“关闭”。“另存为当前文档”不再放在文件树底部。

### 5.3 文件夹

建议菜单顺序：

1. 新建 TXT；
2. 新建 DOCX；
3. 新建文件夹；
4. 分隔线；
5. 重命名；
6. 移动到；
7. 在资源管理器中显示；
8. 分隔线；
9. 删除到回收站。

### 5.4 键盘等价入口

- `Enter`：打开文件或展开/折叠目录；
- `F2`：重命名；
- `Delete`：请求删除并打开确认；
- `Shift+F10` 或菜单键：打开上下文菜单；
- `F5`：刷新工作区；
- `Ctrl+Shift+S`：另存为当前文档；
- `Escape`：关闭菜单、取消拖拽或关闭当前非模态交互。

快捷键不得绕过保存中、未保存、冲突、路径和删除确认门禁。

## 6. 文件树内部拖拽移动

### 6.1 本任务范围

本任务只实现工作区文件树内部的移动：

- 普通文件拖到目录：移动到该目录；
- 文件夹拖到其他目录：移动到该目录；
- 文件或文件夹拖到工作区根部投放区：移动到根目录；
- 拖动后仍调用既有 `relocate` 流程。

从 Windows 资源管理器向文枢拖入文件涉及复制/移动选择、跨盘行为、覆盖、外部路径和导入安全，不属于本任务。

### 6.2 拖拽反馈

- 拖动源显示轻量拖拽预览，正文或绝对路径不得进入日志；
- 可接受的目标目录显示明确投放高亮；
- 工作区根提供可发现但不长期占位的根投放区；
- 非法目标显示禁止状态；
- 离开目标或按 `Escape` 时立即清理全部拖拽装饰；
- 投放后显示移动中状态，避免重复提交。

### 6.3 拒绝与确认规则

以下情况不得提交移动或必须由既有流程拒绝：

- 拖到自身当前位置，视为无操作；
- 目录拖到自身或后代；
- 目标存在同名条目；
- 源或目标为不允许操作的 symbolic-link、junction 或其他类型；
- 受影响标签正在保存；
- 工作区、源或目标在拖动期间已经变化；
- 路径迁移、边界校验或发布前复验失败。

移动成功后必须保持稳定 tabId、标签顺序、活动标签、dirty、正文/模型、光标、滚动、撤销历史和当前查找状态；DOCX 伴随 `.wenshu.bak` 继续按既有规则迁移；工作区搜索按 mutationEpoch 规则失效。

## 7. 视觉与组件基线

### 7.1 设计变量

至少建立：

- 基础背景、表面、边框和文本颜色；
- primary、success、warning、danger、info 语义色；
- hover、active、selected、focus-visible、disabled 状态色；
- 4/8 像素节奏的间距变量；
- 正文、辅助文字、标签、标题字号；
- 圆角、阴影、层级和动画时长；
- 高对比度和 `prefers-reduced-motion` 适配入口。

### 7.2 基础组件

统一以下组件的尺寸与完整状态矩阵：

- 图标按钮、文字按钮、危险按钮；
- 输入框、选择框、复选框、颜色输入；
- 标签、菜单、tooltip、toast；
- 横幅、空状态、加载状态、错误状态；
- 确认对话框和名称输入对话框；
- 分隔条、滚动区和侧栏调整手柄。

## 9. 测试要求

### 9.1 自动化测试

- 右键菜单按对象类型展示正确命令；
- 菜单打开、方向键、Enter、Escape、Shift+F10 和焦点恢复；
- F2、Delete、F5、Ctrl+Shift+S 不绕过门禁；
- 拖动文件、拖动目录、投放到目录、投放到根；
- 自身/后代、同名、saving、迟到结果和非法类型拒绝；
- 拖拽取消、组件卸载、工作区切换后无残留高亮或事件监听；
- 移动后稳定 tabId 和编辑器会话保持；
- mutationEpoch 与工作区搜索失效语义保持；

## 10. 完成标准

- 顶部只有一套一致语言的菜单，不存在可见占位命令；
- 左下角文件操作按钮区完全取消，文件树获得对应可用高度；
- 新建、重命名、移动、删除、在资源管理器中显示和另存为均有清晰的新入口；
- 文件与目录可以通过文件树内部拖拽安全移动，并有完整键盘备用入口；
- 工作区、搜索、TXT、DOCX 和文件管理共享一致设计语言；
- 活动、选择、焦点、悬停、禁用、加载、成功和错误状态均可辨识；
- `900×600` 下无横向溢出、控件遮挡或不可达操作；
- 常见 Windows 缩放比例下布局稳定；
- 关键页面具备可重复截图基线；
- 现有类型、行为、安全和回归测试不弱化，`check` 与 `build` 通过；
- 主进程路径校验、安全写入、revision 冲突、备份、回收站删除、稳定 tabId 和搜索失效语义无回归。

## 11. 明确非目标

- 从 Windows 资源管理器拖入文件或把文件拖出应用；
- 跨工作区、跨盘复制或移动；
- 文件复制粘贴和批量文件操作；
- 自动保存、会话恢复和文件系统监听；
- 深色主题、完整设置系统和主题插件；
- 工作区批量替换、正则/模糊/语义搜索；
- 精确 Word 分页、复杂 DOCX 无损编辑；
- Windows 安装包、自动更新或正式发布流程；
- AI 与 Agent 功能。

这些能力应在 Task 11 形成稳定界面与视觉门禁后分别规划，避免在一次任务中同时改变信息架构、持久状态和文件系统语义。
