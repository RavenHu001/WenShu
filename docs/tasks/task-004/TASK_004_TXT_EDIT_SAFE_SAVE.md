## 一、任务目的

Task 3 已建立“文件树选择 TXT → preload 窄接口 → 固定 IPC → 主进程安全读取 → 中央单只读标签显示”的完整只读链路。本任务在不扩大到多标签页、自动保存、文件管理或 DOCX 的前提下，把这条链路扩展为第一个可安全落盘的编辑闭环：

```text
文件树选择工作区内普通 UTF-8 TXT
  -> 主进程返回正文、格式元数据和内容版本
  -> CodeMirror 6 编辑单个文档
  -> 修改状态与 Ctrl+S / 保存按钮
  -> 固定 document:save-text IPC
  -> 主进程重新校验路径和磁盘版本
  -> 同目录临时文件写入、刷盘、关闭、原子替换
  -> 返回新的正文快照和版本
  -> 仅在对应版本确实已保存时清除未保存状态
```

本任务的首要目标不是增加丰富的编辑器功能，而是证明以下性质能够同时成立：

- 用户可以编辑当前单个 TXT 并显式保存；
- 保存失败、保存竞态或外部修改不会清除未保存内容；
- 写入过程中不会先截断或删除原文件；
- 渲染进程仍然不能直接访问 Node.js、任意磁盘路径或通用 IPC；
- Task 2、Task 3 的工作区和读取安全边界不发生回归。

## 二、完成后的用户体验

任务完成后，用户应能够：

1. 从文件树打开一个工作区内的普通 UTF-8 `.txt` 文件；
2. 在中央单标签编辑器中修改正文；
3. 通过保存按钮或 Windows 快捷键 `Ctrl+S` 显式保存；
4. 在标签和状态区域看到“已保存、未保存、正在保存、保存失败或外部冲突”；
5. 保存成功后继续编辑，并正确区分已保存版本与新的未保存修改；
6. 保存失败时继续看到并保留全部本地编辑内容；
7. 文件被其他程序修改后，保存时收到冲突提示，而不是静默覆盖外部内容；
8. 在存在未保存修改时打开其他 TXT、切换工作区或关闭窗口，得到明确的放弃修改确认；
9. 取消确认后继续留在当前文档，不丢失正文、选区或修改状态；
10. 对不支持安全编辑的文件继续得到明确错误，而不是降级为任意文件写入。

本任务仍保持单文档单标签。选择其他 TXT 会替换当前文档，但必须先通过未保存保护。

## 四、固定设计决策

### 4.1 单文档单标签，不提前实现多标签状态

- 仍只维护一个当前文档；
- 不建立标签数组、标签排序、分屏、最近文件或会话恢复；
- 选择第二个 TXT 前先处理当前未保存修改；
- 成功打开第二个 TXT 后替换第一个文档状态；
- 保存状态只属于当前工作区、当前相对路径和当前内容版本。

### 4.2 使用 CodeMirror 6 作为 TXT 编辑器

- 按项目技术基线使用 CodeMirror 6，不继续扩展只读 `textarea`；
- 仅配置纯文本编辑、原生选择、复制剪切粘贴、撤销重做和保存快捷键；
- 编辑器不得直接读取或写入文件；
- 编辑器变化只更新渲染进程内存状态；
- 不在本任务加入语法高亮、当前文件查找替换、多光标定制、自动补全或复杂快捷键体系；
- 依赖必须使用稳定兼容版本并写入 `package-lock.json`，不得使用 `--force` 或 `--legacy-peer-deps` 绕过冲突。

### 4.3 显式保存，不实现自动保存

- 保存入口为界面按钮和 `Ctrl+S`；
- 未修改文档触发保存时不执行磁盘写入；
- 同一文档同一时刻最多允许一个保存请求在途；
- 保存期间允许继续编辑，但旧保存成功只能确认它提交的那一版内容；
- 若保存请求发出后正文又变化，保存成功后仍保持未保存状态；
- 不实现定时、失焦或切换时自动保存。

### 4.4 内容版本与外部修改冲突

- 主进程读取文件时对原始完整字节计算 SHA-256 内容版本；
- 版本值是冲突检测令牌，不是安全授权，也不能替代路径重新校验；
- 保存请求必须携带上次成功读取或保存返回的预期版本；
- 保存前主进程重新有界读取当前磁盘文件并计算版本；
- 当前版本与预期版本不一致时返回 `CONFLICT`，不创建或替换目标文件；
- 冲突界面保留本地编辑内容，并允许用户放弃本地修改后重新读取；
- 本任务不提供“强制覆盖外部版本”入口。

该方案检测保存时已经发生的外部变化，不等同于文件系统实时监听，也不承诺解决恶意本地进程制造的所有操作系统级 TOCTOU 竞态。

### 4.5 UTF-8、BOM 与换行符

- 仍只支持严格 UTF-8，最大文件大小保持 5 MiB；
- 读取快照记录是否存在 UTF-8 BOM；
- 保存时保留原文件的 BOM 策略，不因进入编辑器而静默移除 BOM；
- 对一致的 LF 或 CRLF 文件，保存后保持原换行风格；
- 新建文件不在本任务范围内；
- 对混合换行文件，首次保存前必须给出兼容性提示，并在用户明确确认后按任务实现选定的规则规范化；不得无提示改写整份文件的换行符；
- 任务实现前必须把混合换行的检测、确认和序列化规则写入测试，不能依赖浏览器或编辑器的隐式转换。

### 4.6 安全写入协议

TXT 保存采用以下固定顺序：

1. 从主进程当前会话取得工作区根路径；
2. 把渲染进程参数视为不可信输入，重新校验规范相对路径、扩展名和工作区词法边界；
3. 从工作区根开始逐段 `lstat`，拒绝符号链接 / junction，并确认中间段为目录、目标为普通文件；
4. 使用真实路径再次确认目标仍位于真实工作区根内；
5. 有界读取当前文件并检查预期内容版本；
6. 按确定的 BOM 和换行规则编码 UTF-8，拒绝超过 5 MiB 的结果；
7. 在目标文件同一目录创建不可预测且排他创建的临时文件；
8. 写完全部字节并对临时文件执行 `sync`；
9. 关闭临时文件句柄；
10. 使用同文件系统替换操作把临时文件替换为目标文件；
11. 返回基于实际保存字节生成的新快照和内容版本；
12. 任一步失败都转换为稳定错误，尽力清理本次临时文件。

禁止以下做法：

- 直接对目标文件使用截断写入；
- 先删除目标文件再重命名临时文件；
- 在系统临时目录写入后跨文件系统移动；
- 使用渲染进程提供的绝对路径、临时文件名、编码或写入选项；
- 替换失败后降级为不安全的覆盖写入；
- 在日志或错误结果中泄漏正文、系统绝对路径、临时文件名或调用栈。

Windows 是主要验收平台。若 Node.js 在支持的 Windows 版本上不能提供满足本任务要求的目标替换语义，应停止 WP2，记录证据并向项目所有者说明替代方案、数据安全风险和迁移成本，不得自行采用“删除后重命名”。

### 4.7 保存失败与未保存保护

- 保存失败不得回退编辑器正文；
- 保存失败不得更新已保存版本；
- 保存失败、冲突或 IPC Promise 拒绝后仍保持未保存标记；
- 打开其他 TXT、成功切换工作区和关闭窗口不得静默丢弃未保存修改；
- 本任务采用“放弃修改 / 取消”保护：用户需要保存时先取消操作、显式保存，再重试；
- 取消后不调用后续文件读取或工作区切换；
- 关闭窗口保护必须由窄接口或明确的窗口状态协调实现，不暴露通用事件总线、`ipcRenderer` 或动态通道。

### 4.8 工作区切换和刷新语义

- 无未保存修改时，成功切换工作区清除当前文档；
- 有未保存修改时，未确认放弃前不得打开原生工作区选择器或改变当前工作区；
- 用户确认放弃后，只有工作区确实成功切换才清除文档；取消目录选择或切换失败仍保留当前文档；
- 手动刷新工作区不自动重读、保存或丢弃当前编辑内容；
- 刷新后目标从文件树消失时，编辑内容仍保留，后续保存返回稳定错误；
- 本任务不加入文件系统监听。

## 五、共享数据契约

共享契约必须保持纯 TypeScript、只读、可序列化，并与 Electron、Node.js、React 和浏览器运行时解耦。

建议在既有 `TextDocumentSnapshot` 上增加或等价表达：

```ts
interface TextDocumentSnapshot {
  readonly name: string;
  readonly relativePath: string;
  readonly content: string;
  readonly byteLength: number;
  readonly revision: string;
  readonly hasUtf8Bom: boolean;
  readonly lineEnding: 'lf' | 'crlf' | 'mixed' | 'none';
}
```

保存请求与结果建议采用：

```ts
interface SaveTextDocumentRequest {
  readonly relativePath: string;
  readonly content: string;
  readonly expectedRevision: string;
  readonly confirmMixedLineEndingNormalization?: true;
}

type SaveTextDocumentResult =
  | { readonly status: 'saved'; readonly document: TextDocumentSnapshot }
  | { readonly status: 'error'; readonly error: SaveTextDocumentError };
```

实现可以在保持同等安全语义的前提下调整字段组织，但必须满足：

- 文件名、版本、BOM 和换行元数据由主进程产生或验证；
- 请求不接受工作区根路径、绝对路径、目标文件名、临时文件名、编码、大小上限或写入策略；
- 结果不包含 `Error`、`Buffer`、`Uint8Array`、文件句柄、`Stats`、函数或类实例；
- 不能仅依赖 TypeScript 类型，IPC 入口必须执行运行时形状和参数数量校验；
- 正文最大值在主进程按 UTF-8 编码后的字节数执行，不使用 JavaScript 字符串长度替代。

保存错误至少稳定区分：

- `NO_WORKSPACE`；
- `INVALID_REQUEST`；
- `INVALID_PATH`；
- `OUTSIDE_WORKSPACE`；
- `UNSUPPORTED_TYPE`；
- `NOT_FILE`；
- `NOT_FOUND`；
- `ACCESS_DENIED`；
- `TOO_LARGE`；
- `CONFLICT`；
- `MIXED_LINE_ENDINGS_CONFIRMATION_REQUIRED`；
- `WRITE_FAILED`。

错误消息只供用户理解；界面控制逻辑依赖错误码，不匹配字符串。

## 六、主进程实现要求

### 6.1 扩展 TXT 读取器

- 在不削弱 Task 3 校验顺序的前提下计算原始字节 SHA-256；
- 检测 BOM 和换行类型；
- 继续严格拒绝非法 UTF-8 和超过 5 MiB 的文件；
- 保持有界读取，不能为了计算版本改为无界 `readFile`；
- 快照正文供编辑器使用，原始字节不得跨进程传递；
- 既有 Task 3 读取安全测试全部继续通过并扩展元数据断言。

### 6.2 新增 TXT 安全保存器

- 保存器位于主进程文档模块，与 React 和 Electron IPC 注册分离；
- 通过轻量文件系统适配器使临时文件创建、完整写入、`sync`、关闭、替换和清理分支可确定性测试；
- 临时文件必须与目标同目录、排他创建且名称不可由渲染进程指定；
- 处理短写，直到全部字节写完或返回失败；
- 在替换目标前完成版本冲突检查和临时文件刷盘；
- 替换成功后返回与磁盘字节一致的新版本；
- 替换前失败时原目标内容和元数据保持不变；
- 替换失败时不得删除原目标；
- 清理失败不能覆盖主要错误，但应通过不含路径和正文的安全诊断记录供开发排查；
- 不把正文写入日志。

### 6.3 固定 IPC

- 新增且只新增具体用途通道 `document:save-text`；
- 只接受一个结构化保存请求；
- 入口验证参数数量、对象形状、必需字段类型和禁止的多余危险参数；
- 处理器开始时捕获当前工作区根路径；
- 调用安全保存器完成全部路径、版本和写入校验；
- 所有预期与意外失败均返回 `SaveTextDocumentResult`；
- 不注册 `file:write`、`fs:*`、通用命令执行器或动态通道代理；
- IPC 注册保持幂等。

### 6.4 窗口关闭保护

- 主进程只维护当前窗口是否存在未保存文档的最小状态；
- 渲染进程与主进程通过固定窄协议协调当前修改状态和关闭请求；
- 窗口关闭且状态为未保存时显示“放弃修改 / 取消”确认；
- 取消后窗口保持打开；确认放弃后只允许本次关闭继续；
- 窗口关闭协调不得获得文件内容、工作区根路径或通用 IPC 能力；
- 协议必须覆盖“刚输入后立即关闭”的竞态；仅使用可能滞后的 fire-and-forget dirty 布尔通知不足以作为关闭许可；
- 应防止关闭确认递归触发或应用退出死锁。

## 七、preload 与渲染进程边界

### 7.1 preload API

`DesktopApi.document` 在既有 `readText(relativePath)` 之外增加：

```ts
saveText(request: SaveTextDocumentRequest): Promise<SaveTextDocumentResult>
```

窗口关闭保护可使用单独的固定命名空间和布尔参数接口，具体命名由实现决定。必须满足：

- 每个函数映射固定通道；
- 不接受动态通道名；
- 不暴露 `ipcRenderer`、Node.js 模块或任意文件系统操作；
- API 对象和命名空间继续冻结；
- 全局类型、共享契约和 preload 实现保持一致。

### 7.2 编辑器状态模型

当前单文档状态至少区分：

- `welcome`；
- `loading`；
- `loaded-clean`；
- `loaded-dirty`；
- `saving`；
- `save-error`；
- `conflict`；
- `read-error`。

建议同时维护：

- 最后一次成功读取或保存的快照；
- 当前编辑器正文；
- 编辑修订编号；
- 当前在途保存所捕获的正文和编辑修订编号；
- 最近一次读取或保存错误；
- 当前文件树选中路径；
- 异步读取请求编号和保存请求状态。

保存成功清除未保存状态的充分条件是：返回结果属于当前工作区和当前文档，且当前编辑修订编号仍等于该保存请求捕获的编号。否则只更新已保存基线，不得清除后来产生的修改。

### 7.3 CodeMirror React 集成

- 编辑器实例的创建、更新和销毁应封装在独立组件中；
- 文档切换时明确替换编辑器状态，不把上一文档撤销历史带入下一文档；
- React 只接收必要的正文变化和快捷键回调；
- 避免每次按键销毁并重建编辑器实例；
- 组件卸载后不提交状态；
- 编辑器内容不得通过 `innerHTML` 注入；
- 空文件应可正常获得焦点并输入；
- 只读加载和错误状态不得创建可写入错误文件的编辑器。

### 7.4 未保存保护与交互

- 标签标题用稳定标记表示未保存，例如文件名后显示 `●`；
- 状态区显示保存状态和可恢复错误；
- 打开另一 TXT 和切换工作区前使用应用内确认；
- 窗口关闭使用主进程受控确认；
- “取消”保持编辑内容、当前文件、工作区和选择状态；
- “放弃修改”只影响用户明确确认的当前过渡；
- 冲突状态不得自动触发放弃或覆盖；
- 快速重复点击保存不得创建并行写入。

## 八、测试要求

### 8.1 基线和读取回归

### 8.3 安全保存器测试

至少覆盖：

- 中文、空正文、BOM、LF 和 CRLF 正确序列化；
- 混合换行未经确认不写入；
- 保存后返回的新版本与实际文件一致；
- 未打开工作区、非法请求、绝对路径、反斜杠、`.`、`..` 和空段被拒绝；
- 非 TXT、目录、符号链接 / junction 和非普通文件被拒绝；
- 真实路径逃逸被拒绝；
- 编码后恰好 5 MiB 可保存，超过上限在创建临时文件前被拒绝；
- 文件不存在和权限错误映射为稳定错误；
- 当前磁盘版本不同返回 `CONFLICT` 且不写临时或目标文件；
- 临时文件排他创建且位于目标同目录；
- 短写会循环完成，不产生截断文件；
- 写入、`sync`、关闭和替换任一步失败时原文件不被删除或截断；
- 失败后尽力清理临时文件；
- 替换失败不降级为直接覆盖；
- 意外异常不泄漏路径、正文、临时文件名或调用栈。

不得为符号链接测试申请管理员权限。难以稳定构造的 Windows 错误使用适配器 mock；正常保存和替换必须另有真实临时目录集成测试。

### 8.4 IPC 与 preload 契约测试

- `saveText` 只映射 `document:save-text`；
- 只传递一个结构化请求；

- API 不允许指定通道、根路径、绝对目标、临时路径、编码和替换选项；
- `DesktopApi`、preload 和渲染端全局类型一致；
- 窗口 dirty / 关闭协调只接受固定形状数据并映射固定通道；
- 不暴露通用 `invoke`、`send`、`on` 或 `ipcRenderer`；
- 结果对象只包含可序列化数据。

### 8.5 编辑与界面测试

- 打开第二个 TXT 时的取消和放弃分支；
- 切换工作区时的取消、放弃、目录选择取消和切换失败分支；

### 8.6 窗口关闭测试

- 放弃修改后只继续一次关闭；
- 多次关闭事件不产生递归确认、重复监听或退出死锁；
