```text
文件树选择工作区内普通 UTF-8 TXT（多次选择）

  -> 每标签独立 CodeMirror 会话（光标/选区/滚动/撤销历史缓存，外部替换重建）

  -> 关闭 dirty 标签 / 切换工作区 / 关闭窗口的聚合确认与 saving 阻止
```

## 3. 标签身份、状态不变量与关闭选择规则

- **标签身份**：以文件树提供并经既有规则规范化的 `relativePath` 作为稳定身份（第 4.2 节），`id === relativePath`；工作区会话内同路径唯一（loading/已加载/错误态都只能一个标签），同名不同路径可并存（`title` 显示完整路径）。数组下标只用于关闭时的相邻选择，不作为身份。
- **状态不变量**（第 5 节，全部由 `validateTextDocumentsState` 校验并有测试）：
  1. `tabs` 中 `id` 与 `relativePath` 唯一；
  2. `tabs` 为空时 `activeTabId === null`；
  3. `tabs` 非空时 `activeTabId` 引用现有标签；
  4. `saving === true` 时该标签存在且只有一个在途保存（与 runtime `saveInFlight` 双向一致）；
  5. dirty 清除只来自与当前编辑修订匹配的成功保存或明确放弃/重新读取（`saveCompletionClearsDirty`）；
  6. 任一异步结果提交前必须通过工作区会话、目标标签、请求编号三重校验（`asyncResultStillValid`）。
- **关闭选择**：关闭非活动标签不改变活动标签；关闭活动标签优先右侧、无右侧取左侧；关闭最后一个标签回到欢迎页；saving 标签禁止关闭（纯层拒绝 + UI 层阻止双保险）。

## 4. CodeMirror 会话保存与清理策略

- 会话缓存 `Map<tabId, EditorSession>` 持有 `EditorState`（含正文、选区、撤销/重做历史）与 `scrollSnapshot()` 滚动效果；挂载时若缓存状态、序列化正文与换行配置一致则恢复（含滚动 dispatch），否则以磁盘正文创建新状态（清空旧历史）。
- CodeMirror 通过 `EditorState.lineSeparator` 与 `sliceDoc()` 显式保持一致 LF/CRLF；mixed 快照按既定 dominant 规则在编辑器内统一表示，并在保存 IPC 前依据原始快照元数据要求确认，避免首次编辑后绕过规范化提示。
- 切换标签即 `key={tabId}` 重挂载：卸载前捕获状态与滚动，挂载时恢复；普通切换不触发内容上报、不产生 dirty、不清空历史（测试断言）。
- 外部正文替换（重试成功、冲突确认后的重新读取）：缓存状态与正文不一致时只重建目标标签状态。
- 内容变化与 Mod-s 保存请求都经会话对象上的可变出口（`notify` / `requestSave`）上报，切换挂载后仍指向最新回调，编辑器状态内不残留组件闭包。
- 关闭标签或工作区失效后，不在活动标签集合中的会话被自动释放（liveTabIds 剪枝）；DocumentPane 卸载时清空全部会话。
- JSDOM 无法可靠断言的滚动数值由手工桌面验收覆盖（第 8.4 节已声明）。

## 5. 每标签读取/保存竞态处理

- **读取**：请求编号全局单调递增（避免关闭后重开同路径的编号碰撞）；新路径创建 loading 占位标签并发起唯一一次读取，同路径 loading 中重复点击不二次读取；重试与冲突重读期间目标标签进入不可编辑 loading 状态，防止请求结果覆盖期间新输入；结果提交前验证组件仍挂载、工作区 epoch + 目标标签存在 + 请求编号最新，任一失效即忽略（乱序返回、关闭后迟到结果、工作区切换或组件卸载后旧结果均安全忽略）。
- **保存**：每标签 `saveInFlight` 防同标签并发，无全局保存锁（A、B 可各有一个在途请求）；请求捕获目标标签、正文（runtime `latestContent`）、编辑修订号与已保存 `revision`；成功只有当前修订号仍等于捕获值才清除 dirty，基线 revision 照常更新；失败/冲突/混合换行只更新目标标签。
- **工作区失效**：epoch 递增使旧工作区全部未完成结果作废；saving 标签存在时所有破坏性过渡被 UI 阻止（controller 的 epoch 门禁作为纵深防御保留，harness 测试直接验证）。

## 6. dirty 聚合与确认目标绑定

- `window.setDirtyState` 上报 `tabs.some(tab => tab.dirty)` 聚合值；切换工作区与关闭窗口的确认文案携带未保存标签数量。
- 所有应用内确认（关闭标签、冲突重读、混合换行、等待保存完成）都携带稳定 `tabId` 或聚合数量，确认/取消时不重新查询活动标签；同一时刻只允许一个确认流程，后续请求不覆盖尚未处理的目标；对话框打开期间切换标签不改变目标（测试断言"确认仍只保存/重读/关闭原标签"）。
- 目标标签在确认前已失效时，纯层转移对未知 tabId 安全无操作，不会作用到其他标签。
