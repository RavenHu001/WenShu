## 使用方式

- 每次复制一个工作包下的完整文本块，交给拥有本仓库访问能力的开发 Agent；无需同时粘贴其他工作包。
- 每段都要求读取统一规范。其“只执行本包”优先于整任务提示词中连续执行全部工作包的要求；本包完成后交接，不自动开始下一包。
- 默认顺序：WP0 → WP1 → WP2 → WP3 → WP4 → WP5。WP2/WP3 仅在 WP1 契约稳定且文件所有权清楚后可以并行；共享文件由一个集成者修改。
- 前序报告不是实现证据的替代品：先核对当前代码、差异和相关测试。已完成部分继续沿用，不从头重做，也不因切换 Agent 就重复全部基线测试。
- 各包将简短结果集中写入 `TASK_013_COMPLETION_REPORT.md` 及 `.en.md`：写明本包状态、接口/文件变化、实际测试结果、未验项和下一包输入。在最终验收前，总状态保持“实施中”或“待验收”；不要求每包再建立独立报告。

```text

实现范围：
1. 完成数据目录初始化、安装版定位文件与原生引导、ready 前 userData/sessionData 重定向、按需日志/转储路径和单实例行为。

3. 安装版首次/重选先完成原生选择，写好最多 8 KiB 的 bootstrap.json 后退出重启，业务窗口不在引导进程创建。首次取消退出；主动重选取消保留旧路径、清标志、重启旧路径；失效根选址取消回到重试/退出。便携目录不可写则提示移动整个目录或退出。重选仅标记下次启动，不实施搬迁。

6. 提供 WP2/WP3 所需的最小共享契约和主进程服务/窄 IPC：读取偏好与状态、更新偏好、受当前会话约束的快照、数据目录展示/打开/下次重选及坏文件重置。正文恢复调度由 WP3 完成，实际窗口布局和最终关闭联调由 WP4 完成；不要为这些后续行为返回虚假的成功结果。
7. 工作区扫描/搜索精确排除当前数据根子树；仍展示同名用户目录。隔离开发、测试、截图路径，保留或同步迁移现有 --user-data-dir 测试覆盖；新增数据目录进入忽略和打包禁止项。

本包接入后即可安全运行：启动默认值、布局更新或退出 flush 都不得覆写损坏/未知更新版本的原件。startupMode 更新及 lastWorkspace 清除/裁剪策略由主进程单处负责，交接给 WP2/WP3 复用，不能由两包各写一套。

验证：
- 真实启动验证三种路径策略、首次选择后重启、目录不可写/缺失与取消分支；检查实际 userData/sessionData 位置。
- 定向覆盖缺失/损坏/未知版本/超大 JSON/额外字段、危险路径/链接、并发写顺序、半途失败和 flush；确认失败不截断旧文件、不允许旧会话快照绑定新根。
- 运行受影响的类型、行为和包排除检查；不修改全局 TEMP/TMP、不清理真实用户资料、不新增数据库/状态框架。

本包交接要列出最终字段/默认值、错误形状、接口名称、数据根解析与测试覆盖方式、会话标识归属，以及哪些接线留给 WP2/WP3/WP4。更新同一份中英文完成报告中的 WP1 状态和实际结果。设置页面与标签恢复未实现时明确说明，不能把 Task 13 整体标为完成。
```

## WP4：布局与关闭集成

```text
你正在 WenShu 仓库工作。本次只执行 TASK-013 的 WP4：布局与关闭集成。完成本包后交接，不自动执行 WP5 最终发布验证。

前置：核对 WP1 存储/flush、WP2 设置入口与 WP3 恢复/记录保护均已实际接入。先处理影响本包安全的集成问题，不重写已验证的模块。记录仍只使用两个 JSON 文件和同一套主进程状态服务。

实现范围：
1. 主进程保存窗口 normal bounds 与最大化状态；创建窗口时结合当前 display work area 校正，处理已拔屏幕、异常数值与缩放，不恢复最小化或全屏。
2. 恢复侧栏宽度/折叠，复用 180–420 px clamp，每次启动进入文件侧栏。初始化期间不把默认布局覆盖保存值；不扩展文件树展开状态或精确阅读位置。
```
