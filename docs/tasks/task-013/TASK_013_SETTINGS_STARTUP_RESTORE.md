## 1. 目标与范围

让用户下次启动文枢时继续上次的文件工作，并能调整基本显示偏好。设置和恢复记录集中保存在一个明确的数据目录，Electron 可配置的运行数据也归入该目录。

| 本期交付   | 固定范围                                                                             |
| ---------- | ------------------------------------------------------------------------------------ |
| 设置入口   | “视图 → 设置…”与 `Ctrl+,`，复用现有模态对话框；不新增活动栏页或路由系统              |
| 主题       | 浅色、深色、跟随系统；默认跟随系统，系统切换时更新                                   |
| TXT 显示   | 预设字体族与 12–24 px 字号；默认沿用实现前的实际显示值，缺失字体使用系统回退         |
| 启动行为   | 一个三选一设置：空白启动、恢复工作区、恢复工作区与标签；默认第三项                   |
| 布局恢复   | 窗口正常位置/大小与最大化状态、侧栏宽度/折叠；每次启动进入文件侧栏                   |
| 文档恢复   | 仅最后一个工作区；标签相对路径、顺序和活动文档；重新读取磁盘上的 TXT/DOCX            |
| 存储可见性 | 设置中显示实际数据目录、固定“打开数据目录”入口、安装版“下次启动重新选择数据目录”入口 |

本期不做：自动保存、未保存正文/草稿恢复、精确光标/选区/阅读位置恢复、跨启动撤销历史、最近工作区列表、多工作区历史、文件树展开状态、标签拖拽/固定/批量关闭、文件监听、DOCX 显示缩放、配置同步、缓存管理页面和自动数据迁移。

TXT 字体/字号是显示偏好，不写入文档。DOCX 继续使用文档模型中的正文格式；主题不能修改模型或导出结果。设置界面用一句话说明：“启动恢复重新打开磁盘文件，未保存内容仍需手动保存。”

## 2. 已核对的接入基础

- `src/main/index.ts`：固定窗口尺寸，尚未重定向 `userData` / `sessionData`；需在启动最前面插入数据路径初始化。
- `src/main/workspace/workspace-session.ts` 与 `workspace-ipc.ts`：根路径只在内存中，来源是原生选择器；恢复需要增加“主进程保存的上次根目录”这一受控来源。
- `src/renderer/lib/use-workspace.ts`：已有工作区打开/刷新、generation、epoch；恢复应复用扫描成功后的同一提交逻辑。
- `src/renderer/lib/use-documents.ts`：`openFile` 已提供 TXT/DOCX 打开、唯一标签和读取生命周期；不用另一套恢复编辑器。
- `src/renderer/lib/use-editor-sessions.ts`：会话含运行时对象，不可直接持久化；DOCX 会话与兼容性确认同样重新建立。
- `src/renderer/components/shell/AppMenuBar.tsx`、`components/common/ModalDialog.tsx` 与 `lib/sidebar-size.ts`：复用入口、焦点语义和 180–420 px 侧栏约束。
- `src/renderer/styles/tokens.css` 已有设计变量，但 `app.css` 等仍有硬编码颜色；深色主题需检查真实编辑区域和提示状态。
- `electron-builder.yml` 是 portable + per-user NSIS；允许选择安装目录，卸载不删 AppData，但不能据此认为安装目录内部的数据会保留。

## 3. 数据目录：尽量减少 C 盘占用

### 3.1 三种运行方式

| 方式                              | 数据根目录规则                                                                     | 系统用户目录中的应用自有数据                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 开发运行                          | 仓库根下 `.local-data/dev/`；从稳定项目路径解析，不依赖启动时的当前目录            | 无需定位文件                                                                                               |
| 便携版                            | 实际 portable 启动器 EXE 同级 `WenShuData/`；随整个目录一起移动                    | 无需定位文件                                                                                               |
| 安装版 / 无 portable 标识的独立包 | 首次运行用原生目录选择器选一个独立数据目录；在安装目录之外，后续由小型定位文件找回 | 仅 `<appData>/WenShu/bootstrap.json`，包含版本、数据根路径和可选的下次重选标志，最多 8 KiB，通常仅数百字节 |

选择界面优先引导使用非系统盘的独立目录，例如 `D:\WenShuData`；这是示例，不硬编码 D 盘、不自动选择磁盘。只有 C 盘时允许用户主动选用。非 C 盘安装可以将所在盘作为目录选择器起始位置，不自动把数据写进安装目录。

便携版使用 `PORTABLE_EXECUTABLE_DIR`，不能用实际运行的解包后 EXE 路径推算持久目录；现有 builder 的 portable 启动器在临时目录运行应用并在退出后清理。此行为可在锁定依赖的 `node_modules/app-builder-lib/templates/nsis/portable.nsi` 中复核。

便携目录不可写时，明确提示移动整个便携目录到可写位置或退出；不静默改用 C 盘，不增加第二套便携定位机制。安装版数据盘缺失或不可写时进入“重试 / 选择数据目录 / 退出”的原生引导，选择取消时保留原定位信息。原数据不自动搬移、删除或覆盖。

### 3.2 单一布局

```text
<数据根>/
  settings.json          # 用户偏好
  state.json             # 窗口/侧栏、上次工作区与标签元数据
  runtime/               # Electron userData
    session/             # 显式指定的 sessionData，含 Chromium 缓存
    logs/                # 若产生日志，限定在这里
    crashDumps/          # 若产生崩溃转储，限定在这里
```

不在每个工作区新建配置目录。文档和既有 DOCX `.wenshu.bak` 继续留在原位置，设置切换与启动恢复不写文档。

数据目录使用普通本地目录，不通过目录链接实现重定向；安装版拒绝数据根与安装程序目录重叠，开发版和便携版使用上述固定子目录布局。若用户打开的工作区包含当前数据根，文件树扫描与搜索精确排除该真实数据子树，不按 `WenShuData` 名称全局屏蔽同名用户文件夹。

### 3.3 启动顺序与重新选址

1. 主进程入口同步解析便携标识、开发路径或安装版定位文件。开发/便携首次使用可创建规定的数据根；安装版定位文件指向的旧数据根若已不存在，应进入重新选择引导，不自动建空目录冒充原数据。根目录有效后才创建所需运行子目录。
2. 已知数据根时，在 `ready` 前设置 `userData` 和 `sessionData`，并在使用日志/转储前设置相应路径；然后才初始化 session、窗口和 IPC。取得单实例锁，后续实例只聚焦现有窗口，避免同一数据目录被多个本用户进程写入。
3. 安装版首次启动或要求重选时，单独走引导分支：`whenReady` 后仅显示无父窗口的原生对话框，不创建业务 `BrowserWindow`、不访问 `session.defaultSession`。选定并验证目录、写好定位文件后退出并重新启动，下一进程从步骤 1 进入。
4. “下次启动重新选择”只写定位标志；不立即重启、不关闭标签。正常关闭仍经过现有 dirty/saving 保护。目标目录可为空或包含有效的本应用设置；对未知版本或不兼容内容报错，不合并两套数据。
5. 需要保留已有设置时，说明先正常退出，再手动复制数据目录并在下次启动选择新位置；应用不实施后台迁移。便携版移动整个程序与数据目录即可。

取消行为固定为：首次选择取消则退出；主动重选取消则保留旧路径、清除重选标志，并重启到旧目录；旧目录不可用时取消选址则返回“重试 / 退出”引导。不存在因取消反复进入重选的循环。

`sessionData` 的设置时机来自 [Electron app 官方文档](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path)；首次选择后重启使后续进程可以满足这一要求。WP0 必须验证此流程，不能在 `ready` 后直接改路径并声称缓存已切换。

**本期承诺是避免非必要的长期 C 盘数据，不承诺 C 盘零写入。** 首次原生引导的运行痕迹、Windows 自身记录，以及现有 portable 自解压使用的系统临时目录可能仍在 C 盘。Task 13 不修改系统 TEMP/TMP、注册表全局目录，也不改造 portable 自解压器；如后续要求连解包临时数据也避开 C 盘，另立小任务评估免解包分发。

旧版本没有本任务的设置/恢复记录，不做旧 Electron profile 的自动扫描、搬迁或清理。开发、测试、截图使用各自隔离数据根；将新目录加入忽略与打包禁止项，不能打进安装包或上传测试证据。

## 4. 最小持久化实现

### 4.1 数据与边界

采用 Node.js 文件 API + 两个版本化 JSON 文件，不引入 `electron-store`、SQLite、Zustand、通用配置框架或事件总线。项目基线列出的 `electron-store` 是原技术建议，当前并未安装；此处明确采用更小的实现，不做等价依赖叠加。

| 文件            | 白名单内容                                                                        | 限制                                                                           |
| --------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `settings.json` | `version: 1`、`theme`、`txtFontPreset`、`txtFontSizePx`、`startupMode`            | 最大 16 KiB；枚举和数值范围精确校验                                            |
| `state.json`    | `version: 1`、窗口 normal bounds/maximized、侧栏宽度/折叠、可空的 `lastWorkspace` | 最大 512 KiB；最多恢复 100 个标签，不限制运行时打开数                          |
| `lastWorkspace` | 主进程记录的根路径、有序 TXT/DOCX 相对路径、可空的活动相对路径                    | 路径去重且有界；超限时保留活动标签并维持其余所选标签的原顺序，明确提示数量限制 |

不存正文、DOCX 模型、HTML、编辑器实例、磁盘 revision、dirty/saving/error、兼容性确认、搜索词/结果、运行时 tabId 或用户操作日志。必要的绝对路径只存在本地定位/状态记录中，不复制到日志、截图证据或遥测；本期不新增遥测。

主进程是唯一磁盘写入者。renderer 只能提交显示偏好和当前工作区的标签/侧栏快照；工作区根、窗口 bounds、数据路径由主进程补齐。接口只接受精确对象，拒绝额外字段、任意根路径、任意配置键和强制覆盖开关。

### 4.2 写入与损坏处理

- 启动时先限制文件大小再解析；文件不存在用默认值。格式损坏、未知版本或非法字段返回明确状态，不能将脏数据直接合并进应用对象。
- 每个文件只使用一个串行写队列，合并短时间内的重复快照（建议 500 ms）；同目录排他临时文件、完整写入、刷盘、关闭后替换。失败保留旧文件和当前内存状态，显示“本次设置/恢复记录未保存，可重试”。
- 状态仅在元数据变化时提交，输入正文不触发状态写入。关闭时刷新最新快照和队列；不能依赖只在退出事件才保存。
- 损坏文件保留原件，设置中提供明确重置入口；未知的更新版本不自动降级覆写。无需多级备份库、迁移链或配置文件实时监听。
- 持久化失败不等于文档保存失败；提示允许重试或继续退出，不能让用户永久无法关闭。强制结束可能丢最后一次元数据变动，不承诺恢复未保存正文。

## 5. 设置界面与显示实现

一个小对话框分为“显示”“启动”“数据位置”三组，使用现有 ModalDialog、按钮、焦点圈定和错误反馈。无需设置搜索、标签式多页、JSON 编辑器或插件扩展点。

显示设置即时预览并保存；保存失败保留当前显示效果并提示。主题以根节点属性和 CSS 变量切换，跟随系统监听 `prefers-color-scheme` 并清理订阅；首次显示前应用读到的偏好，减少主题闪烁。

TXT 只提供有限的字体预设（系统默认、等宽、衬线）和字号，不枚举操作系统全部字体、不接受任意 CSS。通过样式或编辑器公开重配置接口生效，不能重建 EditorState/Tiptap 实例，不能清除撤销/选区或制造 dirty。

DOCX 页面、显式文字颜色与高亮需一起验证可读性；优先保留白色文档画布和原正文颜色、对周围外壳应用主题，不全局反色。深色模式同时覆盖 CodeMirror、查找高亮、菜单、对话框、错误/禁用状态和高对比度模式。

## 6. 启动恢复流程

### 6.1 恢复与记录规则

1. 先读设置与布局，窗口正常 bounds 由主进程结合当前显示器 work area 校正；不恢复最小化或全屏，避免窗口出现在已拔除的屏幕上。侧栏继续使用原 clamp。
2. `空白启动` 不读取工作区；选用此模式时清除并停止记录 `lastWorkspace`，布局仍持久化。`恢复工作区` 只记录/打开最后根目录，不记录标签；`恢复工作区与标签` 才记录路径列表。切换模式成功持久化后生效。
3. 主进程提供无路径参数的 `workspace.restoreLast()`，从自身状态取根目录，重新验证本地目录、逐段链接/真实路径和类型，扫描成功后才提交工作区；失败不清除旧记录，进入可重试的空状态。手动打开与恢复共享提交逻辑。
4. 恢复标签先做语法、类型和重复校验，再按记录顺序调用既有 `openFile`，首版顺序读取即可。每个标签使用新 tabId、新磁盘快照和正常读取门禁；不重用旧状态对象。默认最多 100 个，避免无限启动负载。
5. 路径合法但文件缺失/拒绝访问/读取失败，保留普通 `read-error` 标签并提供现有重试/关闭入口，其他标签继续恢复；危险路径直接拒绝。当前文件变成目录、链接或不支持类型时不得按旧记录读取。
6. 最后激活记录中的活动路径；不存在则激活第一个保留标签，无标签则显示欢迎区。read-only/degraded 根据新读结果处理，degraded 的旧确认不恢复。
7. 从首次恢复开始到完成，暂停自动快照写入，避免空初始状态覆盖旧记录。恢复未完成时暂时禁用其他文件/工作区打开、文档编辑、保存及文件 mutation；窗口仍可关闭。工作区扫描成功后，标签恢复阶段显示“正在恢复”与“停止恢复”。停止只取消后续标签调度和最终活动标签切换，已发起的一次读取按原 controller 正常完成；已打开的标签（含 loading 占位）保留，随后按当前可见状态记录。无需另建单文件读取取消协议。
8. 复用已有工作区 generation/epoch，并对恢复批次使用一个本地 generation；停止、关闭或新工作区操作先作废旧批次。关闭或切换工作区的读取回包继续由既有 epoch/tab/requestId 门禁丢弃；旧恢复调度不得追加标签或抢焦点。主进程恢复与手动打开的异步扫描也必须在提交前验证代次，不能只靠 renderer 丢弃返回值。

根路径可以来自主进程保存的上次选择，这是相对旧“每次必须打开原生选择器”约束的必要扩展；它不新增 `openPath(string)`。本地 JSON 仍视为不可信输入，恢复只读，绝不因记录存在而自动保存、确认降级或执行文件管理命令。

### 6.2 与既有生命周期衔接

- 重命名、移动、另存为成功后，从已提交的标签状态生成新快照；失败/取消不迁移记录。目录迁移仍遵守路径段边界；删除成功后记录中移除受影响标签。
- 状态快照携带主进程签发的当前工作区会话标识；主进程只接受匹配会话的相对路径。旧工作区迟到的写入必须拒绝，不能将其标签绑定到新根目录。
- 正常关闭保存当前路径列表；dirty 标签确认“放弃”后，下次恢复的是同路径的磁盘内容。取消关闭时继续当前会话，不清空记录。尚未完成恢复就关闭时保留原 `lastWorkspace`，只收尾设置/布局写入；用户明确“停止恢复”后才采纳部分可见现场为新记录。
- saving 标签的关闭/工作区切换保护不变；恢复记录的写入不能被当作文档保存成功。窗口关闭协议只增加元数据队列收尾，不绕过现有确认。
- 若恢复模式开启，手动成功切换工作区后，只保留新工作区快照；工作区打开取消或失败仍保留旧会话。

| 现有 main/workspace、preload、App、styles、测试/打包脚本 | 最小接线，保持已有职责                                  |

建议窄能力为：`appState.get()`、`updatePreferences(validatedPreferences)`、`checkpoint(validatedSessionSnapshot)`、`openDataDirectory()`、`chooseDataDirectoryOnNextStart()`、`resetInvalidFile(settings|state)`，加上 `workspace.restoreLast()`。命名可调整，但数据目录选择必须由主进程原生 UI 完成；renderer 不接收任意文件系统访问能力。若某项可由现有关闭协议或启动数据直接完成，不再新增重复方法。

## 9. 验收清单

- [ ] 非 C 盘开发/便携/安装数据根下，设置、恢复记录及可配置 Electron profile/cache/log/dump 路径实际生效；检查实际路径与运行前后目录变化，不只检查配置代码。
- [ ] 安装版 C 盘只新增有界定位文件及明确记录的必要启动/系统痕迹；数据根独立于安装目录，升级/卸载保留它；便携版持久数据不在解包临时目录。
- [ ] 数据目录含中文/空格、不可写、数据盘缺失、首次选择取消、下次重选取消均有确定结果；不自动移动旧数据、不静默回退 C 盘。
- [ ] 配置不存在、损坏、未知版本、超大文件、额外字段、路径穿越/链接与写入失败不导致正文受损或权限扩张；旧文件不会被不完整产物替换。

- [ ] 混合 TXT/DOCX、同名不同路径、空文件、读取错误、read-only/degraded、外部修改和重命名/移动/另存为/删除后的恢复有行为覆盖。
- [ ] 设置改变和恢复动作不 dirty、不保存正文、不清除当前会话历史；重启后没有旧搜索状态、旧兼容性确认或旧 tabId。

- [ ] 测试和截图数据根位于仓库隔离目录，尊重既有 `--user-data-dir` 测试覆盖或同步迁移所有调用点；不能读取真实用户恢复记录，不能删工作区或用户 profile。
- [ ] 顺序运行并通过 `./scripts/npm.cmd run check`、`./scripts/npm.cmd run build`、`./scripts/npm.cmd run test:e2e`；本任务涉及启动与数据路径，另验内部 portable/NSIS 的实际重启和存储位置。
