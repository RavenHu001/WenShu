## 主提示词

你正在 `WenShu` 仓库继续开发文枢 Windows 桌面应用。请完整实施 **TASK-013：基础设置与启动恢复**，按照 WP0–WP5 推进，完成产品代码、必要测试、实际运行验证和中英文交付文档。不要停在方案、界面外观或局部功能上，也不要扩大成通用配置/会话管理框架。

核心目标：让用户调整少量显示偏好，并在下次启动时恢复最后一个工作区与文档标签。**尽量减少非必要的 C 盘写入**，把设置、恢复记录和可配置的 Electron 运行数据放到明确的数据根目录。恢复只重新打开磁盘文件，不恢复未保存正文。

### 1. 开始前与执行方式

1. 检查当前分支、`git status`、适用的 `AGENTS.md`。保留已有改动；如果 Task 13 已有实现，先检查差异和证据，再继续未完成部分，不能重置用户工作。
2. 完整阅读：
   - `docs/tasks/task-013/TASK_013_SETTINGS_STARTUP_RESTORE.md`；
   - `README.md`；
   - `docs/architecture/PROJECT_BASELINE.md`；
   - `docs/development/TESTING.md`；
   - `docs/tasks/task-012/TASK_012_COMPLETION_REPORT.md`。
3. 阅读规划第 2、7 节列出的接入源码及对应测试，重点理解 main/preload/renderer 边界、workspace epoch、stable tabId、dirty/saving、DOCX 兼容性、路径迁移、窗口关闭和 E2E 启动方式。遇到既有行为不清楚时，再查 Task 9–11 的对应规范/报告，不机械重读全部历史档案。
4. 使用项目本地 `scripts/npm.cmd` 和 `scripts/node.cmd`。先准备仓库内隔离的测试/验证目录，避免读取或写入真实用户 profile；必要时只对子进程指定测试临时路径，不修改用户或系统 TEMP/TMP 设置。
5. 修改产品代码前，顺序运行现有 `check`、`build` 并记录实际结果。基线失败先区分环境问题、已有修改与代码问题；不得靠删除断言、新增跳过、关闭安全配置或无依据放宽 timeout 制造通过。
6. 按工作包持续推进，每包完成后做定向验证并简短记录。不为例行文件拆分、命名或下一包开始反复等待确认。若发现真正的范围冲突、权限阻塞或环境缺失，先完成不受影响的工作，再说明具体问题和所需输入。
7. 默认按 WP0 → WP1 → WP2 → WP3 → WP4 → WP5 执行。WP2/WP3 仅在共享契约稳定后可并行，明确文件所有权，最后统一集成。不要让多个 Agent 同时修改 App、preload 或同一契约文件。

### 2. 保持实现简单

- 使用 Node.js 文件 API 与 `settings.json`、`state.json` 两个版本化 JSON 文件；不新增 `electron-store`、SQLite、Zustand、通用事件总线、存储后端或配置迁移框架。
- 复用现有 ModalDialog、菜单、样式变量、工作区 controller 和 `useDocuments.openFile`。按职责写少量模块，规划中的文件拆分可以合并，不创建空抽象。
- 设置入口为“视图 → 设置…”和 `Ctrl+,`；一个对话框包含“显示 / 启动 / 数据位置”。
- 实现浅色/深色/跟随系统，默认跟随系统；TXT 字体仅系统默认/等宽/衬线预设与 12–24 px 字号，默认保留现有实际显示值。
- 启动方式只提供三项：空白、恢复工作区、恢复工作区与标签；默认第三项。空白模式清除并停止记录 lastWorkspace；仅工作区模式不记录标签，布局仍保留。
- 恢复最后一个工作区、标签顺序/活动路径、窗口正常 bounds/最大化和侧栏宽度/折叠；不恢复最小化、全屏或旧搜索状态。
- 本期不做自动保存、草稿正文、精确光标/选区/滚动、跨启动撤销历史、最近工作区列表、多工作区历史、目录展开状态、文件监听、DOCX 显示缩放或自动数据迁移。
- TXT 显示设置通过样式或编辑器公开重配置生效，不重建会话、不制造 dirty、不清空选区或撤销历史。DOCX 正文格式与导出结果保持不变；深色外壳下优先保留白色 DOCX 画布和原文字颜色。

### 3. 数据位置和启动顺序必须实际落地

遵守规划第 3 节，不把“只改设置 JSON 的路径”当成完成：

| 运行方式                        | 固定策略                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 开发版                          | 稳定解析仓库根，数据放 `.local-data/dev/`，不依赖启动 cwd                                                    |
| 便携版                          | 用 `PORTABLE_EXECUTABLE_DIR` 找到实际启动器旁 `WenShuData/`，不使用临时解包后的 EXE 位置                     |
| 安装版/无 portable 标识的独立包 | 首次原生选择独立数据根；必须在安装目录之外。系统用户目录只保存 `<appData>/WenShu/bootstrap.json`，最多 8 KiB |

- 数据根内采用规划规定的 `settings.json`、`state.json`、`runtime/` 和其 `session/`、`logs/`、`crashDumps/` 子目录。日志/转储仅按需产生，不为本任务增加正文日志或遥测。
- 非 C 盘是引导方向，不硬编码 D 盘、不擅自选盘；用户只有 C 盘时允许主动选择。目录不可用时不静默回退 C 盘。
- 入口同步解析并校验已知数据根，在 `ready` 前设置 `userData` / `sessionData`，之后才初始化 session 和业务窗口。路径确定后取得单实例锁，后续实例只聚焦已有窗口。
- 安装版首次或重选使用独立原生引导分支：`whenReady` 后仅开原生对话框，不创建业务 BrowserWindow、不访问 defaultSession；验证目标并安全写定位文件，退出并重启，由下一进程完成 ready 前路径设置。
- 旧安装数据根消失时进入引导，不能重建空目录冒充原数据。首次选择取消退出；主动重选取消保留旧路径、清标志、重启旧路径；旧目录不可用时取消选址回到“重试 / 退出”。
- “下次启动重新选择”仅写标志，不立即退出、不迁移数据。正常关闭仍走 dirty/saving 保护。便携目录不可写时提示移动整个便携目录或退出。
- 开发/便携允许各自固定子目录布局；安装版数据根不得与安装目录重叠。工作区包含当前数据根时，仅按真实路径排除这一数据子树，不全局屏蔽同名用户目录。
- 不迁移或清理旧 profile，不更改系统临时目录，不改造 portable 解包器。现有 portable 可能先向系统 TEMP 解压，因此只承诺减少非必要的长期 C 盘数据，不能声称 C 盘零写入。
- 阅读锁定 Electron 类型定义与 builder 的 portable/NSIS 模板，并对照规划第 10 节官方资料验证启动顺序及卸载行为；不借本任务重做 Task 12 或无关升级依赖。

### 4. 持久化与安全约束

- `settings.json` 最大 16 KiB；`state.json` 最大 512 KiB；恢复最多 100 个标签，超限保留活动标签与所选标签相对顺序并提示。这不是运行时打开标签上限。
- 文件与 IPC 均先做大小/版本/精确字段/枚举/数值/路径校验。本地 JSON 不可信，不能展开到任意对象或将绝对路径参数开放给 renderer。
- 主进程是唯一落盘者，拥有数据目录、根路径和窗口 bounds；renderer 仅提交白名单偏好及绑定主进程当前工作区会话标识的标签/侧栏快照。旧工作区快照不得绑定到新根。
- 不持久化正文、DOCX 模型/HTML、运行时 tabId、revision、dirty/saving/error、兼容性确认、搜索词/结果、撤销历史或编辑器对象。
- 每文件一个串行队列，短时间合并重复元数据快照，同目录排他临时写入、刷盘、关闭、替换，失败保留原文件与内存状态。正文输入不触发元数据写入，关闭前提交最终快照并 flush。
- 损坏记录保留原件并提供明确重置；未知更新版本不自动降级覆写。写入失败可重试或继续退出，不冒充文档保存成功，不永久阻止关闭。
- 保持 nodeIntegration 关闭、contextIsolation 与 sandbox 开启、窄 preload/IPC、工作区边界、symlink/junction/realpath 校验、revision 冲突、DOCX 预算/备份/产物复验和回收站删除语义。
- 不把本地绝对路径或正文写入日志、提交文件或发布证据。截图使用可公开的合成资料；数据根、缓存和测试产物加入忽略/打包禁止项，不能进入 ASAR/安装包。

### 5. 恢复与关闭的确定行为

1. 设置和布局加载完成后才进入恢复。窗口 bounds 校正到当前显示器可见范围，侧栏复用 180–420 px clamp。
2. 使用无路径参数的 `workspace.restoreLast()`，主进程从校验后的自身记录取根路径，复用安全扫描与成功提交；根失效时保留上次记录，给重试/正常打开入口。
3. 按记录顺序复用 `openFile` 重读 TXT/DOCX。新 tabId、新磁盘快照、新兼容性结果；read-only 仍只读，degraded 重新确认。合法路径读取失败保留原位置的 read-error 标签，其余继续；危险路径拒绝，不自动创建缺失文件。
4. 恢复成功后激活保存的活动路径；不可用则选择第一个保留标签，无标签则欢迎页。重复调用、StrictMode 或迟到结果不得重复打开或抢焦点。
5. 恢复期间暂停自动快照写入，并暂时禁用其他文件/工作区打开、编辑、保存和文件 mutation；窗口仍可关闭。工作区扫描成功后的标签阶段提供“停止恢复”。
6. “停止恢复”只停止后续标签调度与最终激活；已发起的一次读取按既有 controller 完成。保留已打开/正在加载的标签，并以当前可见现场继续记录，不新增单文件读取取消协议。
7. 未完成恢复就关闭窗口时保留原 lastWorkspace，只收尾设置/布局；主动停止恢复后，才将部分可见现场作为新记录。
8. 主进程扫描与 renderer 恢复批次均有代次检查，读取继续用既有 epoch/tab/requestId。切换/关闭后的旧扫描、读取、快照或最终激活不得污染新会话。
9. 从成功提交的标签模型投影路径列表，复用重命名/目录移动/另存为/删除结果，不另写一套路径迁移逻辑。失败或取消不迁移记录。
10. 普通关闭继续检查 dirty/saving；确认放弃后下次只打开磁盘版本，取消则保留当前编辑。状态 flush 失败单独反馈，不改变正文保存结论，也不承诺强制结束前最后一次元数据必定落盘。

### 7. 最终验证与交付

最终顺序执行，前一步失败先处理再继续：

```powershell
.\scripts\npm.cmd run check
.\scripts\npm.cmd run build
.\scripts\npm.cmd run test:e2e
```

启动与数据路径必须补充真实验证：

- 实际关闭/重启两次，检查偏好、工作区、混合 TXT/DOCX 标签、活动文档和布局；验证磁盘外部修改后读入新内容。
- 验证恢复中关闭/主动停止、未保存退出取消/放弃、保存中关闭保护、坏记录、不可写/缺失数据目录、三种选址取消，以及旧异步结果。
- 开发、E2E 和截图分别使用仓库隔离目录；尊重现有 `--user-data-dir` 覆盖或同步更新全部调用点。对设置/状态/profile/session/cache 实际路径和运行前后目录增量取证，不能仅断言 `setPath` 被调用。
- 使用当前内部打包命令生成并核验 portable/NSIS；在隔离测试安装位置验证重启、升级/卸载保留外置数据。不得卸载用户正在使用的副本、清理用户 profile 或移动真实文档；无需创建公开 Release 或移动旧 tag。
- 在 900×600、1280×820 和必要的缩放/高对比度情形检查设置、深色主题、DOCX 画布、TXT、查找高亮及错误状态。记录真实测试系统，不将 Windows 11 结果表述为 Windows 10 实机验证。

交付时：

1. 提供实现代码与有意义的行为/失败测试；保持原有安全断言，避免仅复述实现结构的测试。
2. 新增 `docs/tasks/task-013/TASK_013_COMPLETION_REPORT.md` 及 `.en.md`，记录最终决策、WP 结果、测试命令/实际结果、存储位置证据、已知限制和需要人工验证的条目。未验项不得标记通过，尚有必需验收时状态写“待验收”。
3. 同步更新 Task 13 规划状态、项目 README、任务/文档索引、必要的项目基线与测试指南，中英文一致。只更新本任务相关事实，不改写历史验收或发布授权。
4. 检查格式、链接、`git diff --check` 和最终差异，确认无真实数据、缓存、隔离测试目录或无关依赖变化进入提交内容。
5. 最终说明完成内容、验证结果和剩余限制。无法完成某项真实环境验证时，完成所有可执行工作并准确列出所需环境/操作；不得以“建议后续测试”掩盖未完成的门禁。

按上述顺序开始实施并持续推进。详细行为与限额以 Task 13 规划为准；本提示词不授权范围之外的功能扩展、公开发布或清理用户数据。
