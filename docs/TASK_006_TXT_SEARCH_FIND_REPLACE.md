## 一、任务目的

Task 5 已建立“工作区文件树 → 多 TXT 标签 → 每标签独立 CodeMirror 会话 → 安全保存”的多文档编辑基础。本任务在不加入 DOCX、工作区替换、自动保存、文件管理或会话恢复的前提下，补齐 TXT 文档的查找与搜索闭环：

```text
当前活动 TXT 的实时正文
  -> 查找匹配、上一个/下一个
  -> 替换当前项或全部替换
  -> 正常产生 dirty、撤销历史并继续显式保存

当前工作区内已保存的普通 UTF-8 TXT
  -> 主进程受控异步遍历与有界读取
  -> 按文件返回行列、片段、revision 与匹配范围
  -> 点击结果打开或激活唯一标签
  -> revision 与正文范围仍有效时选中并滚动到匹配
  -> 结果过期时只提示，不错误定位、不覆盖正文
```

本任务的核心目标不是只添加一个搜索框，而是建立可取消、有上限、不会冻结界面、不会越过工作区边界，并能与多标签编辑会话可靠衔接的 TXT 搜索能力。

## 二、完成后的用户体验

任务完成后，用户应能够：

1. 在活动 TXT 标签中按 `Ctrl+F` 打开查找面板，输入查询并在匹配之间前后跳转；
2. 按 `Ctrl+H` 打开替换面板，替换当前匹配或全部匹配；
3. 替换结果立即反映在正文和 dirty 标记中，并可通过撤销恢复；
4. 在不同标签之间切换时，各标签的查找条件、当前匹配、选区和编辑历史互不污染；
5. 点击活动栏“搜索”或按 `Ctrl+Shift+F` 打开工作区搜索侧栏；
6. 对当前工作区内已保存的普通 UTF-8 `.txt` 文件执行文字搜索；
7. 在搜索期间看到明确的进行中状态，并可主动取消；新搜索自动作废旧搜索；
8. 查看按文件分组的结果，包括相对路径、行号、列号和单行上下文片段；
9. 看到扫描文件数、命中文件数、命中总数、跳过数量和结果是否被上限截断；
10. 点击搜索结果后打开或激活对应唯一标签，并在结果仍有效时选中匹配、滚动到可视区域；
11. 搜索后文件发生外部变化或未保存编辑使原范围失效时，得到“结果已过期”的非破坏性提示；
12. 切换工作区、取消搜索或连续快速提交查询时，不看到旧工作区或旧查询的迟到结果。

## 四、固定产品与协议决策

### 4.1 一个任务包含两个互补搜索面

本任务同时实现：

- **当前文件查找替换**：只作用于活动标签的编辑器实时正文，包含未保存修改；
- **工作区 TXT 搜索**：只读取当前工作区磁盘上已保存的普通 UTF-8 TXT，不隐式合并未保存正文。

二者共享“查询、匹配、定位”的概念，但数据来源、权限和生命周期不同，不得用一个含糊的全局状态混合处理。

### 4.2 当前文件查找替换边界

- 使用 CodeMirror 6 的公开搜索扩展和命令，建议将 `@codemirror/search` 作为直接依赖；
- `Ctrl+F` 打开查找，`Ctrl+H` 打开替换；已有 `Ctrl+S` 和 `Ctrl+W` 行为保持；
- 至少保证普通文字查询、大小写匹配、上一个/下一个、替换当前项和全部替换；
- CodeMirror 搜索面板若提供正则或 whole-word，可在当前文件内保留，但它们不扩展为本任务的工作区搜索协议；
- 替换必须通过普通编辑事务进入撤销历史，不能直接改 React 状态或绕过编辑器；
- 无实际正文变化时不得制造 dirty；全部替换应作为可预测的单次编辑操作撤销；
- 普通标签切换复用缓存的 EditorState，因此查找面板、查询、选择和历史按 tabId 隔离；
- 关闭标签或切换工作区时，相关搜索状态随编辑器会话一起清理。

### 4.3 工作区搜索数据来源

- 工作区搜索针对**磁盘已保存快照**，不承诺包含已打开 dirty 标签中的未保存编辑；
- 搜索侧栏必须明确表达这一点，避免用户把结果误认为未保存正文的实时索引；
- 工作区搜索不触发保存、自动保存、重新读取或冲突覆盖；
- 搜索开始后文件可能变化，因此每个文件结果必须携带读取时的内容 `revision`；
- 搜索不建立持久索引，不写入工作区，也不创建隐藏缓存文件。

### 4.4 首版查询语义

- 查询必须是 1 至 256 个 UTF-16 code unit 的单行字符串；空字符串、纯换行或包含 `\0` 的值拒绝；
- 首版工作区搜索只实现 literal 文字匹配，支持大小写敏感开关，不接受用户正则表达式；
- 匹配按原字符串中的 UTF-16 范围记录，与 JavaScript 字符串和 CodeMirror 位置一致；
- 匹配为不重叠结果，同一文件内按起始位置升序；文件按规范相对路径自然排序；
- 行号和列号均从 1 开始；CRLF 视为一个换行边界；
- 大小写不敏感匹配必须返回原正文中的实际范围和文本，不能因大小写折叠改变偏移；
- 查询输入本身不写入日志；搜索结果片段由 React 文本节点渲染，不使用 `dangerouslySetInnerHTML`。

### 4.5 固定资源上限

首版采用以下可审计常量：

| 项目                |                 上限 |
| ------------------- | -------------------: |
| 查询长度            | 256 UTF-16 code unit |
| 单次候选 TXT 文件数 |                 1000 |
| 单个 TXT 大小       |  复用现有 5 MiB 上限 |
| 单文件返回匹配数    |                  200 |
| 单次返回匹配总数    |                 2000 |
| 单条预览长度        | 160 UTF-16 code unit |
| 文件读取并发        |                    4 |

- 到达文件数、单文件匹配数或总匹配数上限时返回 `truncated` 与具体原因，不静默丢弃；
- 不因首版 1000 文件规模提前引入数据库、倒排索引、worker thread 或常驻后台服务；
- 若实测主进程事件循环或内存不满足目标，应先记录规模、耗时和瓶颈，再调整实现。

### 4.6 搜索请求与取消

- renderer 为每次搜索分配单调递增的 `requestId`，不得用查询字符串作为身份；
- 同一窗口同一时刻最多一个活动工作区搜索；新搜索先取消旧搜索；
- preload 提供固定的开始与取消方法，不暴露 `ipcRenderer`、通用通道或事件总线；
- 主进程按发送窗口和 `requestId` 跟踪任务；取消其他窗口或不存在的请求必须安全无操作；
- 取消是协作式的：已经开始的单次受控文件读取可以完成，但其结果不得继续提交；
- 主进程在目录批次、文件读取前后和匹配循环中检查取消或工作区变化；
- renderer 同时使用请求 ID 与工作区 epoch 校验迟到结果，不能只依赖主进程取消；
- 窗口销毁、工作区成功切换和组件卸载均必须清理活动任务引用。

### 4.7 工作区与路径安全

- 搜索根路径只能来自主进程的 `workspace-session`，请求不得携带根路径或绝对路径；
- 只遍历当前工作区，不跟随符号链接、junction 或其他重解析点；
- 只把普通 `.txt` 文件作为候选，扩展名比较大小写不敏感；
- 候选文件读取应复用现有 `readTextDocument` 或提取出的等价安全原语，继续执行相对路径、逐段 `lstat`、真实路径边界、普通文件、5 MiB、严格 UTF-8、BOM 和 revision 校验；
- 不得因为目录扫描已看到文件，就跳过读取时重新校验；
- 根目录不可读导致本次搜索失败；子目录、单文件权限、非法 UTF-8、过大、消失等错误隔离并计入跳过统计；
- 跨进程错误只返回稳定 code、可展示消息和数量，不返回绝对路径、原始异常、调用栈、Buffer 或文件句柄。

### 4.8 结果模型与分组

建议共享契约至少包含：

```ts
interface WorkspaceTextSearchRequest {
  readonly requestId: number;
  readonly query: string;
  readonly caseSensitive: boolean;
}

interface WorkspaceTextSearchMatch {
  readonly from: number;
  readonly to: number;
  readonly line: number;
  readonly column: number;
  readonly matchedText: string;
  readonly preview: string;
  readonly previewMatchFrom: number;
  readonly previewMatchTo: number;
}

interface WorkspaceTextSearchFileResult {
  readonly relativePath: string;
  readonly revision: string;
  readonly matches: readonly WorkspaceTextSearchMatch[];
  readonly truncated: boolean;
}
```

最终结果还应包含 `status`、`requestId`、文件分组、扫描/命中/跳过统计、总匹配数和截断原因。具体命名可在 WP1 调整，但以下属性固定：

- 请求不携带工作区根、绝对路径或文件内容；
- 结果文件身份只使用规范工作区相对路径；
- 匹配范围以完整文件正文为基准；
- 预览范围以 `preview` 自身为基准；
- 请求和响应均为只读、可序列化、运行时可验证的数据。

### 4.9 搜索结果定位与过期规则

点击结果时创建稳定定位请求，至少绑定：

- 唯一定位请求 ID；
- 工作区 epoch；
- 搜索 `requestId`；
- 规范相对路径；
- 文件 `revision`；
- `from` / `to`；
- 实际匹配文本。

定位规则固定为：

1. 调用多文档 controller 的“打开或激活”，同一路径仍只对应一个 tabId；
2. loading 标签等待读取完成，不创建第二标签；
3. 标签有成功文档快照且其磁盘基线 revision 与结果 revision 一致时，继续验证当前正文范围；
4. `tab.content.slice(from, to)` 与结果实际匹配文本一致时，选中范围、滚动到可视区域并聚焦编辑器；
5. revision 不同、范围越界或当前正文范围不匹配时，只激活标签并显示非破坏性“搜索结果已过期”提示；
6. read-error 标签保留错误状态，不能伪造已定位成功；
7. 标签关闭、工作区切换、新定位请求或组件卸载会作废旧定位请求。

dirty 标签并非一律拒绝定位：只要原范围在实时正文中仍精确匹配即可定位；否则不得猜测“最近的同名文本”，防止跳到错误位置。

### 4.10 工作区侧栏状态所有权

- 将工作区状态与 `WorkspaceSidebar` 的展示职责分离，建议提取 `useWorkspace` controller 并由 `App` 持有；
- 文件侧栏和搜索侧栏共享同一工作区快照与打开/刷新状态；切换活动栏不得丢失工作区或已展开的文件树；
- 活动栏“文件”和“搜索”改为真实 button，并提供活动状态、键盘焦点和 `aria-pressed` 或等价语义；
- “设置”继续作为不可用占位，不在本任务实现设置系统；
- 搜索侧栏在无工作区时显示明确空状态，不发起 IPC；
- 工作区成功切换清空旧搜索结果；取消选择或打开失败保留原工作区和原搜索状态。

### 4.11 依赖与状态管理

- 可新增 `@codemirror/search` 直接依赖，并在完成报告记录锁文件变化与选择理由；
- 不为本任务引入 ripgrep 二进制、数据库、搜索服务、Zustand 或其他全局状态库；
- matcher、契约验证、结果分组和定位有效性尽量保持为可测试纯函数；
- React hook 负责异步协调，组件负责展示，主进程负责文件系统搜索；不得把遍历或 Node.js API 放入 renderer。

## 五、状态模型与不变量

### 5.1 工作区搜索状态

建议 renderer 状态至少区分：

```ts
type WorkspaceSearchStatus = 'idle' | 'searching' | 'completed' | 'cancelled' | 'error';
```

状态中至少保存当前输入、已提交查询、大小写选项、活动 requestId、结果、统计和可展示错误。输入变化本身不等于搜索完成结果，避免结果标题与实际查询错位。

### 5.2 必须保持的不变量

1. `searching` 状态必须存在唯一活动 `requestId`；非 searching 状态不得保留活动任务句柄；
2. 只有 requestId 与工作区 epoch 同时匹配的结果可以提交；
3. 取消、工作区成功切换或卸载后，旧结果不得恢复 searching 或覆盖新结果；
4. 结果中的相对路径、revision 和匹配范围在整个结果生命周期内不可变；
5. 文件结果唯一，每个相对路径最多一个分组；
6. 文件与匹配顺序确定，不依赖并发完成顺序；
7. 统计数量与实际结果、跳过和截断语义一致；
8. 定位请求始终绑定一个搜索结果和稳定 tabId，不在异步完成时重新读取“当前活动结果”；
9. 当前文件替换只改变目标标签，不改变其他标签正文、dirty、selection 或搜索状态；
10. 工作区搜索永远不修改文件、不清除 dirty、不触发保存或重新读取。

### 5.3 异步提交条件

工作区搜索结果提交前必须同时满足：

- 组件仍挂载；
- 工作区 epoch 未变化；
- requestId 仍是当前活动请求；
- 请求未被取消；
- 返回结果的 requestId 与请求一致。

结果定位提交前还必须满足：

- 目标标签仍存在；
- 标签相对路径仍与结果相同；
- 定位请求 ID 仍是该标签当前请求；
- 标签已加载可编辑正文；
- revision 和正文范围通过第 4.9 节校验。

## 六、模块与文件职责建议

### 6.1 共享搜索契约

建议新增 `src/shared/search.ts`：

- 请求、取消、匹配、文件分组、统计与结果联合类型；
- 稳定错误 code 与截断原因；
- 固定资源上限常量中需要跨进程共享的部分；
- 不导入 Electron、Node.js 或 React。

### 6.2 纯匹配器

建议新增 `src/main/search/match-text.ts` 或可被 main 测试直接导入的纯模块：

- literal 大小写敏感/不敏感匹配；
- UTF-16 范围、1-based 行列和单行预览生成；
- 单文件与总结果预算；

## 七、Electron 与安全边界

### 7.1 新增能力的最小接口

建议的 renderer API 形状为：

```ts
readonly search: {
  readonly textWorkspace: (
    request: WorkspaceTextSearchRequest,
  ) => Promise<WorkspaceTextSearchResult>;
  readonly cancelTextWorkspace: (
    request: WorkspaceTextSearchCancelRequest,
  ) => Promise<void>;
};
```

实际命名可调整，但必须保持固定用例、固定参数、固定返回值，不能演化为通用 `invoke(channel, payload)`。

### 7.2 必须保持的安全属性

- `nodeIntegration: false`、`contextIsolation: true`、sandbox 保持不变；
- renderer 不直接导入 Node.js、Electron、文件系统或 worker_threads；
- 搜索请求不接受根路径、绝对路径、glob、任意扩展名、命令、脚本、编码或读取上限；
- 搜索取消只能引用当前窗口已知 requestId，不成为通用任务控制接口；
- 主进程不执行用户提供的正则表达式或 shell 命令；
- 搜索读取只使用只读文件系统 API，不创建、修改、删除或重命名文件；
- 工作区切换后旧根搜索结果不得进入新会话；
- 不记录查询正文、命中正文、绝对路径或完整文件内容；
- IPC 返回不包含 Node.js 对象、原始异常或内部绝对路径。

## 十二、失败处理与决策规则

- 无工作区时不调用搜索器或返回稳定 `NO_WORKSPACE`，不使用 renderer 提供的根路径；
- 非法请求返回稳定错误，不猜测、截断或修补危险字段；
- 空查询由界面阻止且由 IPC 再次拒绝；
- 根目录失败结束本次搜索；子目录或单文件失败记录跳过并继续；
- 达到资源上限返回部分有效结果和明确截断状态，不无限积累结果；
- 取消不是错误；取消后不得把部分结果标记为 completed；
- 新请求或新工作区已经生效时，任何旧结果必须安全忽略；
- 并发 worker 必须在结束、取消和异常后释放任务引用，不保留文件内容；
- 搜索结果过期时不自动重新读取 dirty 标签、不移动到猜测位置、不覆盖或保存；
- 当前文件替换失败或无匹配时不得破坏正文、dirty 或历史；
- 若 CodeMirror 公开 API 无法可靠完成查找状态保存或定位，先记录限制并设计最小封装，不操作私有 DOM；
- 若需要扩大 IPC、接受绝对路径、加入工作区写入或改变 5 MiB/UTF-8 安全边界，停止当前工作包并先形成设计说明；
- 若接近 1000 文件产生可复现性能问题，先测量目录遍历、读取、匹配、序列化和渲染各阶段，不直接引入持久索引；
- 不得用删除测试、降低 Electron 安全设置、关闭严格检查或扩大超时制造通过结果。
